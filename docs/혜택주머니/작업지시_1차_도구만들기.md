## 4. tools/lt_google_check.mjs — 구글 경쟁 (에고라이트)
- 기존 `tools/collect_research_ego.mjs`, `.claude/skills/weekly-collect/*.mjs`의 ego lite 여는 방식을 그대로 쓴다(비로그인, 끝나면 창 닫기).
- 키워드마다 `https://www.google.com/search?q=…&hl=ko&gl=kr` → 상위 8개 결과의 도메인·제목, AI 개요 있음/없음, "다른 사용자도 함께 질문함" 질문들, 관련 검색어.
- 판정(도메인 분류표를 파일 안에 둔다):
  - 정부·공공(.go.kr, korea.kr, gov.kr, 공단·공사), 대형 언론, 포털(naver.com, daum.net 등), 은행 → "큰 곳"
  - 블로그(tistory, blog.naver, brunch, 워드프레스 개인 도메인 등)·작은 사이트·핀테크 블로그(toss 등) → "작은 곳"
  - 작은 곳 3개 이상 🟢 / 큰 곳 6개 이상 🔴 / 그 사이 🟡 / 계산기 사이트 3개 이상이면 `calc_intent: true`
- 출력 JSON: `[{keyword, verdict, top8:[{domain,title,kind}], ai_overview, paa:[], related:[], calc_intent}]`.
- 키워드 사이 5~10초 쉬기. 구글이 막으면(봇 확인 화면) 거기서 멈추고 지금까지 결과를 저장한 뒤 알린다.

## 6. tools/lt_auto_input.py — 앱 입력 (핵심)
입력: `작업폴더/06_확정.json` + `작업폴더/원고/*.md`.

06_확정.json 형식:
```json
{"week": "2026-11-23",
 "posts": [
  {"order": 1, "slot": "2026-11-23T07:44", "cluster_seed": "대표 키워드", "role": "대표",
   "keyword": "대표 키워드", "action": "approve|add", "queue_id": "있으면", "category": "정부지원금·복지",
   "draft": "원고/01_20261123-0744_대표키워드.md"}
 ]}
```

순서(글마다, `--apply`일 때만 실제로):
1. 키워드: `action=approve`면 그 queue_id를 승인 상태로(이미 승인이면 그대로), `add`면 `/add-custom-keyword`(week, keyword, cluster_seed, role, `confirm_dup=1`)를 부르고 새 id를 받는다. 키워드 표기는 한 글자도 바꾸지 않는다.
2. 원고 파일에서 코드 블록 A(본문)와 B(메타데이터)를 꺼낸다. A는 `/article/<id>/paste`(raw_paste), B는 `/article/<id>/save-metadata/wordpress`(metadata_text).
3. 붙여넣기 결과 `parse_ok`가 아니면 그 글은 멈추고 실패 목록에.
4. 이미지: `/article/<id>/gen-images`. **시험 단계에서는 image_gen 목업 모드로 1편만.** 실제 실행은 사용자 "넣어" 후. 실행 전에 총 장수·예상 비용을 화면에 보여 준다.
5. `/article/<id>/generate-final`.
6. 예약 정보 저장: `articles.json`의 그 글에 `lt_plan = {"scheduled_at": "YYYY-MM-DDTHH:MM", "category": "...", "tag": "대표 키워드"}` (새 칸, 기존 칸은 건드리지 않음).
7. 결과 표: 순서 / 시각 / 키워드 / 단계별 성공·실패 / 최종본 주소(`http://127.0.0.1:5000/article/<id>/final/wordpress`).
- 이미 발행된 글(`platform_post_id.wordpress` 있음)은 건너뛴다.
- 미리보기에서는 위 1~6을 "할 일 목록"으로만 보여 준다.

## 7. 앱 수정 — 최종본 발행 칸 미리 채우기 (templates/final_view.html + app.py view_final)
- 지금 문제: 발행 칸이 **"즉시 발행"이 기본 선택**이고 예약 시각이 비어 있어서, 그대로 누르면 바로 공개된다.
- 바꿀 것(채널 `longterm_wp`이고 글에 `lt_plan`이 있을 때만):
  - "예약 발행" 라디오를 기본 선택, 시각 칸을 보이게 하고 `lt_plan.scheduled_at` 값을 넣는다.
  - 카테고리·태그 칸에 `lt_plan.category`, `lt_plan.tag`를 넣는다(비어 있으면 지금처럼 메모 값을 씀).
  - 칸 위에 한 줄: "예약: 11월 23일(월) 07:44 · 정부지원금·복지" (굵게).
  - 예약 시각이 지금보다 이전이면 빨간 경고 "예약 시각이 지났습니다 — 시각을 고치세요"를 띄우고 버튼을 누르기 전 확인창 대신 버튼을 비활성화한다.
- API 발행 칸과 브라우저 발행 칸 둘 다. 다른 채널 화면은 그대로(출력 같음 확인).
