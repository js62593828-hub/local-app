## 사용자 결정 (11/19)
- 분량: 최근 글의 130% → 대표 4,000~6,000자(목표 4,500), 세부 3,600~4,800자(목표 4,000). (최근 3주 중간값 대표 3,057·세부 2,785)
- 본문 사진: 1장 늘림 → 본문 4,000자 미만 4장, 4,000자 이상 5장.
- 원고는 Opus 5.5가 쓴다.

## 1. 앱 수정 — 혜택주머니 본문 사진 장수 (app.py)
- `LONGTERM_BODY_IMAGES_LONG` 4 → 5, `LONGTERM_BODY_IMAGES_SHORT` 3 → 4 (기준 4,000자 그대로).
- gen_images의 롱텀 분기: 메모 장면 수를 그대로 쓰는 범위 `3 <= n_memo_scenes <= 4` → `3 <= n_memo_scenes <= 5` (옛 글 3장 메모도 그대로 동작).
- 사진을 본문에 넣는 곳(소제목 배치·최종본 만들기·워드프레스 업로드)에 4장 상한 같은 숫자가 따로 있는지 찾아보고, 있으면 5장까지 되게 맞춘다. 다른 채널 숫자는 건드리지 않는다.
- 이미 만든 글은 그대로(이미지 다시 만들기를 눌러야 바뀜).
- `lt_auto_input.py` 미리보기의 이미지 장수·예상 비용 계산도 새 장수로.

## 2. tools/lt_draft_check.py — 원고 검사 (새로)
- `--week` 필수, `--file 원고파일`(없으면 그 주 원고 폴더 전부), 확정 정보는 `06_확정.json`(없으면 `05_기획표.md`에서 역할·묶음·발행 순서를 읽는다. 둘 다 없으면 역할만 파일 구분 제목에서).
- 검사 항목(글마다 ✔/✖ + 숫자):
  1. 본문 글자 수(공백 제외, 원고지침 11번: 코드 블록 A에서 `[플랫폼…]`·`제목:`·첫 줄 최종 확인·출처 한 줄(기준일 …)·면책 `<small>` 줄·`## 마치며`(또는 FAQ 다음 첫 ## 섹션) 제외). 대표 4,000~6,000 / 세부 3,600~4,800.
  2. 본문 사진 alt 줄 수(`"## …" →` 줄): 4,000자 미만 4, 이상 5. 각 줄의 소제목이 본문 ## 줄과 글자 그대로 같은지, 서로 다른지, FAQ·마치며·요약 블록이 아닌지.
  3. 피할 표현(갈리·갈린·갈려·갈립·갈릴·갈렸·가르·가른·가릅, 헷갈·갈라지 제외) 0개.
  4. `카테고리 제안:`이 6개 이름 중 하나.
  5. {{LINK:…}}가 같은 묶음에서 이 글보다 먼저 발행되는 키워드만 가리키는지(대표글의 "## 이 주제의 세부 글" 목록은 예외 — 실제 세부만).
  6. 표지 1줄 18자·2줄 10자 이내(공백 포함), 메타 디스크립션 80~150자, FAQ Q. 4~6쌍, 면책 줄 있음, 첫 줄 "최종 확인:".
- 출력: 글마다 한 줄 요약 + 걸린 항목 설명. 종료 코드는 걸린 게 있으면 1. 파일은 읽기만.
- 시험: 11/16 주 혜택주머니 기존 글 2편(articles.json platform_raw + platform_metadata를 임시 파일로 만들어)으로 1회 — 지금 기준으로는 글자 수·사진 줄이 걸려야 정상.
