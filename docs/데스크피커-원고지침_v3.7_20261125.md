# N데스크피커 원고지침 v3.7 (2026-11-25)

이 파일 하나가 원고·제목·사진·표지 규칙의 원본이다. 로컬앱 `tools/radar_rules.md` 도 같은 내용, 검사는 `tools/radar_check.py`. keyword_pipeline 은 「6. 문장 쓰는 법」「9. 제목」「12. 피할 표현」을 읽는다(소제목 이름을 바꾸면 keyword_pipeline 도 맞춘다). 바뀐 내용의 기록은 인수인계·HANDOFF 에만 둔다.
0~3장의 표시는 앱이 읽는 고정 글자라 한 글자도 바꾸지 않는다(틀리면 앱이 인식하지 못하거나 ③ 화면에 노란 경고).

---

## 0. 원고 파일
- 글 하나에 파일 하나(.md, UTF-8): 본문 칸(1장) → `[메모]` 한 줄 → 메모 칸(2장). `[메모]` 줄이 없으면 위반.
- 저장 위치·파일 이름은 프로젝트 지침 [원고 저장].

## 1. 본문 칸 형식
```
[플랫폼:네이버]
제목: (확정 제목)

(도입 문단)

## 소제목 1
(본문)

## 제품 비교 소제목
### 브랜드 모델명
[사진: 3]
(이 제품 설명)
[상품카드: approved.json 상품명 그대로]

## 사기 전에 알아 둘 점
…
```
- 맨 위 `[플랫폼:네이버]`, `제목: …` 두 줄 필수. 제목은 대기열 확정 제목 그대로, 본문에서 다시 쓰지 않는다.
- 제품 구간 순서: `### 브랜드 모델명`(짧게, 예: `### 벨킨 BPD004`) → `[사진: n]` → 설명 → `[상품카드: …]`. `###` 가 빠지면 제품 소제목이 나오지 않는다.
- `[상품카드: 상품명]` 은 approved.json 상품명과 한 글자도 다르지 않게.
- 별점 띠는 앱이 상품카드 있는 `###` 바로 아래에 자동으로 넣는다. 원고에는 아무것도 쓰지 않는다(내용은 5장).
- 틀 B 본상품 카드는 두 번: 기본 정보 `###` 구간 안에 한 번, 마지막 `##` 구간 맨 끝 줄에 한 번(같은 상품명, `###`·사진 없이. 끝 카드엔 별점 띠 없음).
- 제품이 아닌 사진은 그 `##` 아래 `[사진: n]` 한 줄. 번호는 1부터 차례로(장수는 10장).
- 표는 마크다운 표, 행 10개 안. 표 바로 아래에 그 표의 `[사진: n]`, 메모 `[사진자리]` 종류는 '표'(표 개수 = '표' 번호 개수, 순서대로 짝지음).
- 문단: 이어지는 1~3문장(공백 포함 약 150자 이내)을 한 문단, 문단 사이 빈 줄. 문장마다 줄을 바꾸지 않는다. 앱이 양끝 정렬하고 150자 넘는 문단은 문장 끝에서 나눈다.
- 소제목은 `##`(일반)·`###`(제품)만. `####` 금지.

## 2. 메모 칸 형식 (`[메모]` 줄 아래)
```
카테고리: (갈래 이름)
태그: 태그1, 태그2, … (10~15개, 띄어쓰기 없이)
메타 디스크립션: (한두 문장)
[표지]
범주: (예: 난방, 책상 소품)
제목: (12자 이내)
부제: (16자 이내, 원고에 있는 말)
사진: (흰 배경 사진 우선, 틀 A 는 2~3개를 쉼표로)

[사진자리]
번호 | 종류(제품·표·카드·캡처·AI) | 넣을 소제목(원고 그대로) | 내용(파일명 / 장면 / 카드 종류)
```
- `카테고리:`·`태그:` 줄 필수.
- 태그는 쉼표로 나누고 태그 안에 띄어쓰기 없음(보조배터리 고르는 법 → 보조배터리고르는법. 앱이 빈칸에서도 잘라 조각이 생김). 키워드를 붙여 쓴 태그 1개 포함.
- `카테고리:` 값 = 아래 표의 갈래 이름 그대로(= 네이버 하위 카테고리. 방꾸미기·계절가전은 하위 없이 그 이름).

| 큰 카테고리(네이버 상위) | 갈래(= `카테고리:` 값) | 범위 |
|---|---|---|
| 데스크테리어 | 책상 정리 | 모니터암·모니터 받침대·데스크매트·선반·정리함·케이블정리·펜꽂이·메모보드·독서대·탁상시계·탁상달력 |
| 데스크테리어 | 조명 | 책상스탠드·모니터조명·무드등 |
| 데스크테리어 | 의자·쿠션 | 의자·발받침·등쿠션·방석 |
| PC·디지털 | 모니터·노트북 | 모니터 본체·노트북·미니PC·태블릿 |
| PC·디지털 | 키보드·마우스 | 키보드·마우스·마우스패드·손목받침대·노트북거치대 |
| PC·디지털 | 충전·멀티탭 | 고속·무선충전기·충전스테이션·멀티탭·USB허브·보조배터리 |
| PC·디지털 | 이어폰·스피커 | 이어폰·헤드폰·스피커·거치대 |
| 방꾸미기 | 방꾸미기 | 소파·협탁·수납장 같은 방 가구, 러그·커튼 같은 패브릭, 벽·바닥 인테리어 소품(작업방·원룸 장면) |
| 계절가전 | 계절가전 | 겨울: 발난로·미니히터·손난로·전기방석 / 여름: 탁상선풍기 등 |

- 갈래는 이름이 아니라 실제 종류로(모니터암·받침대는 책상 정리, 모니터 본체만 모니터·노트북, 이름에 '모니터'가 있어도 조명이면 조명).
- 범위 밖: 로봇청소기처럼 방·책상에서 꾸미거나 쓰지 않는 물건. 방꾸미기는 '보이는 것'(가구·패브릭·소품)만, 청소·주방·세탁·생활 수납은 N살림노트 쪽(경계 확인 전 임시 기준).
- `[표지]` 는 줄마다 `이름: 값`, 빈 줄에서 끝. 부제는 원고 속 말을 뜻이 통하는 구절로 줄인다(예: "230g·최대 10시간"). 문장 중간에서 자르지 않는다.
- `[사진자리]` 는 사진 한 장당 한 줄. 번호 = 본문 `[사진: n]`, 소제목은 원고 글자 그대로. 캡처는 그 소제목 내용이 보이는 상세 이미지.

## 3. 강조
- `**글자**` = 굵게+금색. 소제목마다 1~2곳(핵심 숫자·결론).
- `==글자==` = 형광펜+굵게. 글 전체 2~3곳, 주로 결론 문장. 2곳보다 적으면 앱이 아무 데나 하나 더 넣으니 직접 고른다.
- 숫자+단위(170g·최대 30W·27,900원·4.8점 등)는 앱이 자동 강조, `**` 불필요.
- 글자색·글자 크기 지정, HTML 태그 금지.

## 4. 쓰지 않는 것
쇼핑커넥트 안내 문장(앱이 이미지로 넣음) / 다른 글 목록·"함께 보면 좋은 글"·`[내부링크: …]`(앱이 붙임) / GIF 표시, 링크 주소, 본문 맨 위 제목 반복 / 옛 표시 `[이미지: 파일명]`·`[표: …]`.

## 5. 근거와 숫자
- 쓰기 전에 `pipeline/candidates_run/<실행폴더>/research/<상품id>.md` 를 읽는다. 사양·가격·평점·구매자 평가는 이 파일에 있는 것만. 파일이 없으면 쓰지 않고 "자료 수집 요청: (상품id)".
- approved.json 에 확정된 제품만 쓴다(대안 포함). 실제 종류를 확인한다(수집 목록에 분류 오류가 섞임).
- **제품은 한 번만**: 상품카드·표·이름 든 대안 모두 Desk Picker 전체에서 글 하나에만 쓴다(같은 주·이미 발행/예약한 글 모두). 브랜드+모델명이 같으면 판매처·상품id 가 달라도 같은 제품. 기준은 장부 `pipeline/radar_used_products.json`. 장부에 있으면 approved.json 에 있어도 쓰지 않고 "제품 중복: (상품id·글)". 틀 B 본상품 카드 두 번은 중복 아님.
- 대안: 틀 A 는 2~3개 중 다른 브랜드 1개 이상(브랜드 키워드 예외는 7장). 틀 B 는 approved.json 에 있고 장부에 없는 상품만, 다른 브랜드 먼저. 없으면 같은 브랜드도 되지만 숨기지 않고("같은 JBL의 FLIP7은 ~") 크기·사양·쓰는 상황 차이로 쓴다. 쓸 대안이 없으면 대안 구간을 뺀다.
- 사양 출처 순서: 네이버 정보 표 → 상세 이미지 → 제조사 공식.
- 값이 없으면 표에 '표시 없음'('없음'만 쓰면 기능이 없다는 뜻), 흐리거나 출처끼리 다르면 '확인 필요'. 본문에선 그 항목을 다루지 않는다. 값이 없다는 것만 알리는 문장("찾지 못했어요", "적혀 있지 않아요", "이 글에서는 말하기 어려워요") 금지. 숫자를 지어내지 않는다.
- 제목의 궁금증(방수·하중·배터리 등)이나 제품 종류의 핵심 사양(모니터 거치대 하중·지원 인치·VESA, 보조배터리 출력 등)에 답할 값이 없으면 쓰지 않고 "자료 보강 요청: (항목)".
- 옵션·구성마다 값이 다르면 옵션별로 적는다. "최대"·"약"·"○○ 제외"는 상품 페이지 그대로.
- 같은 표 안 단위 통일(무게 g, 길이 mm). 단위를 바꾸면 '약'(0.58인치 → 약 15mm).
- 가격은 "작성일 기준 약 ○○원(변동 가능)"으로만.
- 리뷰 개수는 원고(본문·표)에 숫자로 쓰지 않는다. 표 "평점(리뷰 수)" 칸에도 평점만. 본문·표 평점은 research 값 자릿수 그대로.
- 별점 띠(앱 자동, 참고): 금색(#C9A35B) 별 5개를 평점만큼 채움(4.84면 다섯째 84%). 리뷰 수는 앞 두 자리만 남겨 내리고 '이상'(2,254 → 2,200개 이상, 369 → 360개 이상, 10 미만은 그대로), 끝에 research 수집일 기준(예: 2026.11.17 기준), 이름은 '리뷰'. 값은 모두 research 파일.
- **구매자 평가 옮기는 법**(근거: research '후기 요약 (문장)' 단락의 정도 표시):
  - '많음'·'자주' → 제품 특징·쓰는 장면으로 그냥 말한다(6장). 예: "설치는 모니터 위에 얹기만 하면 끝나요."
  - '일부' → 장점이면 빼거나 "~에도 쓸 수 있어요", 아쉬운 점이면 "~경우가 있어요 / ~수 있어요". 모든 제품의 일처럼 단정하지 않는다.
  - 후기 문장·상품 페이지 AI 리뷰 요약을 따옴표로 옮기지 않는다. 후기에 없는 원인을 붙이지 않는다(켜지지 않는다는 후기에 "전력이 모자라서" 금지).
- 안전·건강 효과(화상 없음, 전자파 0 등)는 인증 표시가 있을 때만 "~로 표시돼 있어요".
- 바뀔 수 있는 규정(기내 반입 등)은 기본으로 빼고, 꼭 필요하면 "작성일 기준".
- 상품 이미지는 research 파일에 적힌 경로.

## 6. 문장 쓰는 법
- ~요체("~습니다"·"~다" 끝맺음 금지). 짧게, 과장 없이.
- **말투: 전하는 말이 아니라 알려 주는 말.** 이 물건을 잘 아는 사람이 설명해 주는 느낌이어야 한다.
  - 사양·구성: 그냥 말한다("전원 단자는 USB A타입이에요." "리모컨 건전지는 들어 있지 않아요."). "상품 페이지에는 ~로 표시돼 있어요"는 안전·효과·인증 같은 판매자 주장일 때만.
  - 구매자 평가 '많음'·'자주': 특징·장면으로("무게 중심이 잘 잡혀 있어 올려 두면 흔들림이 적어요.").
  - 느낌에 가까운 평가(눈이 편하다, 마감이 깔끔하다): "~하기 좋아요 / ~한 편이에요".
  - **전하는 말은 글 하나에 2번까지**(세는 기준은 12장). 출처를 밝히려면 그 구간 첫 문장에 한 번만, 이어지는 문장은 그냥 말한다. 평점은 숫자로("평점은 4.91점이에요").
  - 바꾸기: "~라는 말이 많았어요" → "~해요" / "~평이 이어졌어요" → 지우고 내용만 / "~했다고 해요" → "~해야 해요·~하면 돼요" / "~라는 구매자도 있었어요" → "~에도 쓸 수 있어요·~경우가 있어요" / "~이야기가 보였어요" → 지우거나 "~는 아쉬워요".
- 써 본 척 금지: 써보니, 직접 사용, 제가 써본, ○일 사용, 실사용, 사용기, 내돈내산, ~더라고요/~더라구요, "나·저" 주어. 틀 E 만 예외(8-1장). 사용자가 실제로 쓰는 제품은 사용자가 알려 줄 때만 틀 E 로 쓴다.
- 글을 어떻게 썼는지 밝히는 문장 금지("직접 써 보고 쓴 글은 아니에요", "상품 페이지와 후기를 바탕으로 정리했어요", "'없음'은 값을 찾지 못한 칸이에요" 등). 써 봤다고도 안 써 봤다고도 말하지 않는다.
- 추천은 해도 된다. 근거는 "~해서 ~한 분께 맞아요"처럼 내용으로 밝히고, 전하는 말을 늘려서 밝히지 않는다.
- 아쉬운 점은 숨기지 않되 짧고 담담하게, 같은 문단에 누구에게 문제인지나 대처법을 붙인다(예: 충전기가 들어 있지 않아 책상에 둘 충전기를 미리 챙겨 두면 돼요).
- 장면은 책상과 그 주변. 다른 곳에서도 쓰는 물건은 책상 옆 장면 중심.
- 금지: 최고·무조건·100%·완벽·강력 추천·1위·출처 없는 순위 / 가격 압박("할인 곧 끝", "체감가", "오늘 가격 확인") / 다른 브랜드 깎아내리기 / 빈 문장("무게는 확인하지 못했어요", 판단에 안 쓰이는 색상·출시일·제조국·반품비).
- 글자 수(7·8·8-1장)는 쓰는 장면(책상 크기·작업 종류·시간대), 기준의 이유, 대안과의 차이로 채운다. 되풀이·빈 문장 금지. 자료가 모자라면 범위 아래로 끝내고 "자료 보강 요청: (항목)".
- 첫 문장은 장면 / 질문 / 결론을 돌아가며(장면 조금 더 자주).
- 소제목 문구·순서는 글마다 바꾸고, 같은 날 글끼리 같은 소제목 금지.

**고치기 전 → 고친 뒤 예시**

| 고치기 전(전하는 말) | 고친 뒤(알려 주는 말) |
|---|---|
| 설치는 모니터 위에 얹기만 하면 된다는 말이 많았어요. 무게 균형이 좋아 안정적이라는 평이 이어졌어요. | 설치는 모니터 위에 얹기만 하면 끝나요. 책상에 스탠드를 따로 세우지 않으니 키보드와 마우스 자리가 그대로 남아요. 무게 중심이 잘 잡혀 있어 올려 두면 흔들림이 적어요. |
| 리모컨 조작이 번거롭다는 말이 반복해서 나왔어요. | 아쉬운 건 리모컨이에요. 잠시 두면 절전 상태로 들어가 매번 깨워야 해서, 버튼 한두 번으로 끝나는 조작을 원하면 번거롭게 느껴질 수 있어요. |

## 7. 틀 A — 고르는 법 (2,200~3,000자, `##` 소제목 5~7개)
흐름(문구·순서는 글마다 바꾼다): 1. 필요한 상황 2. 고를 때 볼 기준 3~5개(왜 중요한지) 3. 비교표(제품 2~3개 × 기준 4~8개) 4. 제품 소개: `###` 제품 구간 2~3개(사진·설명·상품카드) 5. 상황별 추천 6. 이런 경우는 피하기 7. 정리(결론 문장 `==형광펜==`).
- 상품카드 2~3개(제품마다 1개).
- 제품: 그 키워드에 확정된 상품 중 실제 종류가 같고 장부에 없는 2~3개(다른 브랜드 1개 이상). 다른 키워드에 확정된 상품은 가져오지 않는다. 2개가 안 되면 쓰지 않고 "틀 A 제품 확정 필요: (키워드)". 제품 하나로 기준만 설명하는 글로 바꾸지 않는다.
- 브랜드 키워드(예: 소니헤드폰)는 그 브랜드 같은 종류 2~3개로, 다른 브랜드 없이 모델끼리 차이(사양·가격대·쓰는 상황) 중심.
- 제품마다 아쉬운 점 1개 안팎(8장 기준).

## 8. 틀 B — 모델명 (1,600~2,200자, `##` 소제목 4~6개)
흐름: 1. 한 줄 결론(누구에게 맞는지) 2. 기본 정보: 본상품 `###` 구간(상품카드 ①) + 정보표(가격·크기·핵심 사양) 3. 장점(6장 말투) 4. 아쉬운 점 5. 비슷한 대안 1~2개와 차이(5장 '대안') 6. 맞는 분 / 안 맞는 분 — 맨 끝 줄에 상품카드 ②.
- 본상품·대안은 장부에 없는 제품만. 다른 글 틀 A 에서 소개한 모델로 틀 B 를 쓰지 않는다.
- 아쉬운 점: 1~2개, 문단 1~2개로 장점보다 짧게. 반복된 것 중 사양·쓰는 상황과 이어지는 것(크기·무게·충전기 별매·소음·호환 등) + 누구에게 문제인지나 대처법. 쓰지 않는 것: 드문 고장·불량 후기, "낮은 평점 후기에서는 ~" 식 묶음, 다른 모델과 비교한 가격 불만, 주관적 음질·디자인 불평.
- 상품카드 ②는 `###`·사진 없이 `[상품카드: 같은 상품명]` 한 줄, 바로 앞 문장은 결론 정리(가격 압박 금지).
- 대안을 사진과 `###` 구간으로 넣으면 그 대안에도 카드 1개(approved.json 에 있고 장부에 없는 상품만). 문장으로만 비교하면 `###`·카드 없이. 이름을 든 대안도 장부에 올라간다.

## 8-1. 틀 E — 경험 글 (2,200~3,000자, `##` 소제목 5~7개)
사용자가 실제로 쓰고 '경험 글'로 정해 준 제품만(지금: 트랜지션 라이트 87).
- 근거: ① 경험 메모 `pipeline/radar_experience/<상품id>.md` ② research 파일(사양·가격·평점). 메모에 없는 경험은 지어내지 않는다. 메모가 없으면 "경험 메모 필요: (상품id)".
- 말투: 1인칭 가능("제가 ~ 써 보니", "제 손에는 ~했어요"). 쓴 기간·옵션·환경은 메모 그대로, 사양은 research 값. 남의 평가는 '전하는 말 2번까지' 그대로.
- 광고·협찬이 아니면 "직접 사서 쓰는 제품"이라고 한 번 밝혀도 된다(받은 제품이면 반드시 밝힌다).
- 흐름: 1. 왜 샀는지·쓰는 환경 2. 기본 정보(`###` + 정보표, 카드 ①) 3. 좋았던 점 4. 아쉬운 점과 대처 5. 맞는 분 / 안 맞는 분 6. 정리(맨 끝 줄 카드 ②).
- 사진: 사용자 사진 먼저(`[사진자리]` 종류 '내 사진', 내용에 파일명). 쇼핑커넥트 대표 이미지는 기본 정보 구간 1장까지. AI 장면 사진 금지.
- 다른 제품 비교는 이름 없이 가능("제가 쓰는 다른 75배열 키보드"). 이름을 들면 장부에 올라간다.
- 카테고리·태그·표지는 틀 B 와 같다.

## 9. 제목
- 40자 이내. 키워드는 글자·순서 그대로 제목 맨 앞 15자 안에(띄어쓰기만 자연스럽게: 맥세이프보조배터리 → 맥세이프 보조배터리).
- 끝맺음 이름(궁금한 점 정리, 대안과 차이 등)을 글자 그대로 붙이지 않고, 원고에서 실제로 답할 **구체적인 궁금증 1~2개**(소음·배터리·크기·호환·하중 등)로 뜻이 드러나게 쓴다. 궁금증은 research 에 답할 값이 있는 것만.
- 틀 B 모델은 장부에 없는 모델만.
- 틀 A: "키워드 + 끝맺음". 아래 6가지 중 하나가 분명히 보여야 한다.
  - ① 추천 — 듀얼 모니터 받침대 추천, 책상 폭별로 고른 3가지
  - ② 고르는 법·기준 — 발난로 고르는 법, 사무실 책상 밑에 둘 때 볼 기준
  - ③ 비교·차이 — 보조배터리 10000 vs 20000, 차이와 선택 기준
  - ④ 사기 전 확인할 점 — 책상 정리함, 사기 전 서랍 깊이·책상 두께 확인
  - ⑤ 답이 보이는 질문 — 발받침대, 어느 높이가 오래 앉기 편할까?
  - ⑥ 숫자 — 무선 마우스, 무게·소음·배터리 3가지
- 틀 B: "브랜드 모델명 + 제품 종류(큰 검색어) + 구체적인 궁금증".
  - 예: 로지텍 G304 무선 마우스, 배터리 얼마나 갈까? / 카멜마운트 PMA2X 모니터암, 책상 두께·하중 정리 / 앤커 A1638 보조배터리, 비슷한 제품과 다른 점 / JBL FLIP7 블루투스스피커, 캠핑과 책상 둘 다 쓸 분께
  - 끝맺음 5가지: 궁금한 점 정리 / 답이 보이는 질문 / 살 만할까 / 이런 분께 맞아요 / 대안과 차이.
- '추천'은 써도 된다(사양·구매자 평가·쓰는 상황을 보고 고른 제품을 권한다는 뜻). 경험을 꾸미는 말(직접, 제가, 써본, 솔직, 찐, 인생)과 함께 쓰지 않는다.
- 금지 단어(원고도 같음): 후기·내돈내산·써보니·사용기·실사용·직접 써본·최고·무조건·100%·완벽·강력 추천·1위. 효과를 단정하는 말도 금지.
- 틀 E 만 예외: '사용기·실사용·써보니·○개월 사용'을 경험 메모의 기간과 맞을 때 쓸 수 있다('최고·무조건·100%·완벽·강력 추천·1위'는 금지). 예: (브랜드 모델명) 키보드 ○개월 사용기, 소리·무게 정리
- 한 주 분산(하루 틀 A 1 + 틀 B 2, 주 21편): 틀 A 7편은 같은 끝맺음 최대 2편, '고르는 법' 제목 최대 2편. 틀 B 14편은 같은 끝맺음 최대 5편, 같은 날 틀 B 2편은 서로 다른 끝맺음.

- 크기: 본문 사진 800x800, 표 그림 가로 800(세로는 표 길이), 별점 띠 400×75, 표지는 1080x1080 으로 만들어 업로드 폴더엔 800×800. GIF·배너·서명은 앱이 정한 크기.

  - 틀 B 기본: 제품 1~2 · 캡처 1~2 · 스펙표 1 · 장단점 카드 1 · AI 0~1
- 제품 사진은 쇼핑커넥트 대표 이미지, 캡처는 상세페이지에서 1~2장. AI 이미지는 본문 장면 사진에만, 글당 최대 2장.
- 표·카드는 앱이 원고로 그린다. 카드 문구는 원고 문장을 줄인 것만, 새 숫자 금지.

## 12. 피할 표현 (제목·소제목·본문·표·메모 전부, radar_check 와 앱 ③ 경고가 같이 점검)
- 금지: "갈리다/가르다" 계열(헷갈리다·갈라지다는 괜찮음), "~다는 점이 가장 큰 ○○", "쓸모", "~구조예요", "지점", "정답", "마주하게", "~더라고요/~더라구요"(틀 E 는 더라고요 허용).
- 바꿔 쓰기: 갈린다 → 달라져요 / 차이가 나요 / ~에 달려 있어요 / 나뉘어요.
- 글 하나에서 쓸 수 있는 횟수: 핵심 1 · 셈 1 · ~게 좋아요 2 · 통해 2 · 에 따라 달라 2 · **전하는 말 2**.
- 전하는 말로 세는 것(본문 전체 합계): "말이 / 평이 / 이야기가 / 이야기도 / 반응이 / 의견이 / 불만도" 뒤에 "많았어요·많아요·있었어요·있어요·나왔어요·이어졌어요·보였어요·반복" 이 오는 문장, "~다고 해요 / ~라고 해요 / ~대요", "~(라는|한) 구매자(도|가) 있었어요", "구매자 평가를 보면 / 구매자 후기에서".
- 표 칸에 '없음'만 쓰지 않는다('표시 없음'으로).

## 13. 다 쓴 뒤
- `python tools/radar_check.py --run <실행 폴더> <원고 폴더>` 로 위반 0개 확인(Claude Code). radar_check 가 보는 것(제품 중복·틀 B 카드 2개·태그·전하는 말·금지 단어·글자 수)은 다시 눈으로 보지 않는다.
- 눈으로 볼 것: 제목이 대기열과 같은지 / 상품카드 이름이 approved.json 과 같은지 / 틀 A 브랜드 구성(7장) / 틀 B 대안이 approved.json 에 있고 장부에 없는지 / `[사진: n]` 번호와 메모 `[사진자리]`·표 아래 '표' 번호 / 값이 없다는 것만 알리는 문장, 후기 따옴표 인용, 리뷰 개수 숫자가 없는지 / 소리 내어 읽었을 때 남의 말을 옮기는 글처럼 들리지 않는지 / '일부' 주제를 단정하지 않았는지 / 아쉬운 점 1~2개에 대처법·맞는 사람이 붙었는지 / `==형광펜==` 2~3곳 / 카테고리 갈래.
