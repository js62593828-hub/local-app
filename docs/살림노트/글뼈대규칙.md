# 글뼈대규칙 (N살림노트 · V2.2 · 2026-11-23)

> 적용: 네이버 "우리집 살림노트"의 A 해결형·B 점검형·C 결정형 원고.
> 목적: 글마다 **뼈대(섹션 순서·모양)와 요약 블록 이름**이 같아서 "같은 틀로 찍어낸 글"처럼 보이는 문제를 없앤다.
> 나눠 맡는 것: 섹션 순서·요약 블록 이름·사진 장수와 구도는 이 파일, 그 밖의 내용 규칙(근거 문장·분량·운영자 경험·피할 표현·가격 금지·제품 자료 규칙·링크 규칙·메타데이터 형식·출처 캡처)은 원고지침.

## 0. 바꾸면 안 되는 것 — 앱이 글자를 읽는 곳

| 글자 그대로 둘 것 | 이유 |
|---|---|
| `[플랫폼:…]` 줄, `제목:` 줄, `태그:` 줄, 메타데이터 메모 항목 이름, `출처 캡처:` 블록 | 앱이 줄 이름으로 읽음 |
| FAQ 소제목은 `## 자주 묻는 질문` + `Q:`/`A:` | 앱이 이 소제목으로 FAQ를 찾고 구글 FAQ 데이터를 만듦 |
| `링크:` 줄은 **C 의 제품 섹션 소제목 바로 다음 줄에만** | `링크:`가 있는 섹션은 앱이 무조건 "상품 카드"로 바꿈 |
| 상품이 아닌 섹션 소제목에 "FAQ"·"자주 묻는 질문"·"자주 하는 질문"이라는 말을 넣지 않음 | 그 섹션이 FAQ로 잘못 읽힘 |

- 앱이 읽지 않는 것(마음껏 바꿔도 됨): `## 먼저 답부터 드릴게요`, 그 밖의 모든 본문 소제목과 순서.
- 제품 섹션의 `## 소제목`은 앱이 상품 카드 제목으로 그대로 보여 줄 뿐이라, 제품명이든 유형 이름이든 그대로 동작한다. 상품 구조화 데이터는 "가격:" 줄이 있을 때만 만들어지는데, 가격은 쓰지 않으므로 만들어지지 않는다.
- `## 자주 묻는 질문`은 모든 뼈대에 넣는다. 위치는 글 끝쪽(마무리 바로 앞).
- 본문 이미지 alt의 소제목은 **원고에 실제로 쓴 소제목** 글자 그대로(뼈대가 바뀌어도 같다).

## 1. 무엇을 바꾸나 — 다양화 4가지

1. **뼈대**: 유형마다 아래 메뉴(2장)에서 하나를 고른다. 섹션 순서와 모양(표·번호·문답·사례)이 달라진다.
2. **요약 블록 이름과 모양**: 3장 목록에서 고르고, 모양(✅ 줄·번호 줄·짧은 문단)도 바꾼다.
3. **양**: 소제목 수(A·B 5~7, C 5~8, 홈판 실험 최대 4), 표 수(0~2), 인용구 수(원고지침 범위)를 글마다 다르게. FAQ는 늘 3~4쌍.
4. **마무리 인사 순서**: 댓글 질문·공감과 이웃 추가·다음 글 예고 세 가지를 모두 넣고, 순서와 문장을 글마다 바꾼다.

## 2. 뼈대 메뉴

각 뼈대에는 원고지침이 요구하는 **내용**(원인·해결·상황 차이·근거 문장 등)이 모두 들어가야 한다. 바뀌는 것은 그 내용을 **어떤 순서, 어떤 모양**으로 보여 주느냐다. "(기본)"은 원고지침의 기본형 순서다.

### 2-1. A 해결형
| 번호 | 이름 | 순서(도입·요약 블록 다음) | 어울리는 키워드 |
|---|---|---|---|
| A1 | 원인부터 (기본) | 원인 → 해결 순서(번호+표) → 상황별로 달라요 → (주의) | 왜 생기는지 궁금한 문제 |
| A2 | 흔한 방법 뒤집기 | 다들 하는 방법과 안 되는 이유 → 제대로 하는 순서 → 집·기기별 차이 짧게 | 잘못 알려진 방법이 있는 문제 |
| A3 | 따라 하기 | 준비물 → 단계 1·2·3(각 단계를 `###`로) → 끝난 뒤 확인할 것 → 다시 안 생기게 | 손으로 하는 작업(뚫기·청소·보수) |
| A4 | 증상별 진단 | 증상 표(이런 모습이면 / 원인 / 먼저 할 일) → 증상별 섹션 2~3개 → 공통 예방 | 원인이 여러 가지인 문제 |
| A5 | 문답으로 풀기 | 본문 소제목을 모두 독자 질문으로, 섹션마다 짧은 답 + 근거 | 궁금한 점이 여러 갈래인 키워드 |

### 2-2. B 점검·시즌형
| 번호 | 이름 | 순서 | 어울리는 키워드 |
|---|---|---|---|
| B1 | 체크리스트 (기본) | 체크 항목 5~7개 → 한눈에 보는 표 | 점검 항목이 많은 것 |
| B2 | 시기 달력 | 언제(주·월별) 무엇을 → 시기를 놓치면 생기는 일 → 표 | 시즌 준비·교체 주기 |
| B3 | 집 한 바퀴 | 현관→거실→주방→욕실처럼 장소 순서로 점검 | 집 전체 점검 |
| B4 | 안 하면 생기는 일부터 | 놓쳤을 때 생기는 문제 → 원인 → 미리 할 점검 3~5개 | 동파·누수처럼 손실이 큰 것 |
| B5 | 시간별 코스 | 10분 코스 / 30분 코스 / 주말 코스로 나눠 점검 | 대청소·계절 정리 |

### 2-3. C 결정형 (숍글)
공통: 사용자가 [제품] 자료로 준 **실제 제품 1~2개**로 쓴다(원고지침_네이버_C [숍글 제품]). 제품마다 `## 제품명` + 바로 다음 줄 `링크:`.
| 번호 | 이름 | 형식 | 순서 | 어울리는 상황 |
|---|---|---|---|---|
| C1 | 상황별 비교 (기본) | ① 두 제품 | 비교표 → 고르는 기준 3가지 → 제품 섹션 2개 → 상황별 고르는 법 → 사기 전에 확인할 것 | 유형이 나뉘는 제품군 |
| C2 | 맞대결 | ① 두 제품 | 두 제품 맞대결 표 → 항목별 비교 3~4개(`###`) → 제품 섹션 2개 → 이런 집엔 이쪽 | 두 방식이 대결 구도로 검색되는 것 |
| C4 | 우리 집 진단 | ① 두 제품 | 우리 집 조건 질문 3개(평수·바닥·가족 등) → 조건별 맞는 제품 표 → 제품 섹션 2개 | 집 조건 따라 답이 다른 것 |
| C3 | 기준 깊게 | ② 한 제품 | 이 제품을 고른 이유 → 고르는 기준 3가지를 길게(숫자·근거) → 제품 섹션 1개(+고른 이유) → 사기 전에 확인할 것 | 고르는 법이 어려운 제품군 |
| C5 | 잘못 고르는 경우 | ② 한 제품 | 흔히 잘못 고르는 경우 3가지(그 결과) → 그래서 이 제품 → 제품 섹션 1개(+고른 이유) → 사기 전에 확인할 것 | 실수가 잦은 제품군 |

## 3. 요약 블록 이름 — 돌려 쓰기

| 이름 1 (기본) | 이름 2 | 이름 3 | 이름 4 | 모양 고르기 |
|---|---|---|---|---|
| 먼저 답부터 드릴게요 | 급하신 분은 이것만 보세요 | 이것만 기억해 두세요 | 한 줄씩 먼저 정리할게요 | "- ✅ " 줄 / "1. 2. 3." 줄 / 짧은 문단 2문장 |

- 줄 수·글자 수 규칙은 원고지침 그대로(3줄, 각 40자 이내 등).
- 쓰지 않는 이름: "바쁘신 분들을 위한 3줄 요약/결론", "상황별 한 줄 답", "결론부터", "핵심 요약", "총정리", "솔직 후기"·"내돈내산"(써 본 것처럼 읽힘).

## 4. 돌려 쓰기 규칙

1. **같은 주·같은 유형에서 같은 뼈대 상한**: A(주 9편 기준) 3편까지 / B(6편) 2편까지 / C(6편) 2편까지. 편수가 다르면 비율로 맞춘다(같은 뼈대가 그 유형의 3분의 1을 넘지 않게).
2. **발행 순서상 연달아 같은 뼈대 금지**: 바로 앞 같은 유형 글과 같은 뼈대 번호를 쓰지 않는다. 유형이 달라도 모양이 비슷한 것(예: A5 문답형 다음에 소제목이 전부 질문인 B 글)은 연달아 두지 않는다.
3. **요약 블록 이름**: 연달아 같은 이름 금지, 한 주에 같은 이름은 편수의 3분의 1까지.
4. **기본형 몰림 막기**: "(기본)" 뼈대는 한 주 편수의 30% 이하.
5. 뼈대는 키워드에 맞는 것을 먼저 고르고, 상한에 걸리면 두 번째로 맞는 것을 고른다. 억지로 안 맞는 뼈대를 쓰지 않는다.
6. **C 형식 정하기**:
   - 형식은 **제품군 성격으로** 정한다: 소재·방식·형태로 유형이 나뉘는 제품군 → ① 두 제품 / 나뉘지 않는 제품군 → ② 한 제품. 비율을 억지로 맞추지 않는다. 사용자가 준 제품 수가 다르면 제품 수를 따른다.
   - 한 주에 한 형식이 C 편수의 5/6 이상이면(6편 중 5편 이상) 원고 준비의 점검 한 줄에 ⚠로 알린다(바꿀지는 사용자).
   - 발행 순서상 같은 형식은 3편 연달아 두지 않는다.
   - 형식이 정해지면 뼈대는 2-3 표의 그 형식 줄에서 고른다. 1번 상한도 함께 지킨다.

## 5. 원고 표·원고 출력

- 원고 표(프로젝트 지침 2-1 ⓑ)의 **"뼈대" 칸**: `번호·이름번호` 형식(예: `A3·2` = 따라 하기 + "급하신 분은 이것만 보세요"). C는 **"제품 수" 칸**(2 / 1)도 채우고, 형식은 제품 수로 정해진다(① 2개 / ② 1개).
- 원고 앞 줄에 "뼈대: A3 따라 하기 · 요약 이름 2" 한 줄(C는 "형식: ② · 뼈대: C3 …").
- 답변 끝 점검 줄에 "뼈대·요약 이름 상한 지킴 ✔ / FAQ n쌍"(C는 "자료에 없는 제품·스펙 0개 ✔"도).
- "이번 주 기록 저장" 파일에 글마다 뼈대(C는 형식·제품명도)를 남겨, 다음 주에 같은 뼈대·같은 제품이 몰리지 않게 본다.

## 6. C 결정형에서 쓰지 않는 것

C는 **사려는 사람이 잘 고르게 돕는 글**이다. 아래는 어느 뼈대에서도 쓰지 않는다.
- 사용자가 [제품] 자료로 주지 않은 제품·스펙·숫자. AI가 제품을 고르거나 더하기. 다른 브랜드 이름·깎아내리기.
- 제품을 써 본 척("직접 써 보니", "솔직 후기", "내돈내산").
- "이런 경우엔 사지 않아도 돼요" 같은 섹션·문단, 제품 없이 해결하는 방법 안내.
- "이런 분께는 안 맞아요"처럼 구매를 말리는 문단.
- 대신 쓰는 것: 상황에 맞는 제품 짝짓기("이런 집엔 이 제품"), **사기 전에 확인할 것**(설치 공간·크기·호환·소음·관리 주기 같은 사실, 후기에서 자주 나온 아쉬움도 "~인지 먼저 확인해 보세요"로), (한 제품일 때) **이 제품을 고른 이유**.
- 정직성 규칙은 그대로: 과장 금지, 확인된 사실만, 한 제품이 모든 집에 최고라고 하지 않기(다른 선택이 더 맞는 상황은 긍정형으로).

## 7. 본문 사진 — 장수·구도·위치

### 7-1. 장수
- A·B·C 모두 `본문 이미지 alt 텍스트 제안:` 아래 **4줄**(= 본문 사진 4장, 표지 포함 5장).

### 7-2. 구도 — 사진마다 다르게
- 장면 문장 맨 앞에 구도를 한 마디로 쓴다. 한 글 안의 본문 사진은 **모두 다른 구도**, 표지와도 다른 구도.
- 구도 목록: 아주 가까이(클로즈업) / 위에서 내려다본 / 눈높이 정면 / 비스듬한 옆에서 / 낮은 곳에서 올려다본 / 공간 전체가 보이게 넓게 / 손이 작업하는 장면 가까이 / 문틈·창 너머로 들여다본
- 예) `"## 원인은 창틀 아래 찬 공기예요" → 위에서 내려다본, 물방울이 고인 창틀 홈과 검게 변한 실리콘 줄눈`
- 장면 문장에 구도가 없으면 앱이 글마다 겹치지 않게 구도를 골라 붙인다.
- C 본문 사진에도 브랜드·로고·판매 상품의 구체적 모양은 넣지 않는다(AI 그림이 실제 제품처럼 보이면 안 됨 — 상품 사진은 사용자가 넣음).

### 7-3. 위치 — 소제목을 고르게, 자리는 섞어서
- 메모 줄의 `"## 소제목"`이 사진이 들어갈 섹션이다. 원고의 ## 줄 글자 그대로.
- 사진 4장은 **서로 다른 섹션**에, 글 앞·중간·뒤에 퍼지게 고른다. 매번 같은 자리를 고르지 않는다 — 뼈대에 맞게 그 글에서 장면이 가장 잘 보이는 섹션을 고른다.
- 고르지 않는 곳: 요약 블록, `## 자주 묻는 질문`, 제품 섹션(`링크:`가 있는 섹션), 마무리.
- 고를 수 있는 섹션이 4개보다 적으면(예: C에서 제품 섹션을 빼고 3개뿐, 홈판 실험 글) 있는 만큼만 쓰고, 원고 앞 ⚠ 줄에 "본문 사진 n장(고를 섹션 부족)"이라고 적는다. 한 섹션에 사진 2장을 넣지 않는다.
- 섹션 안에서 사진이 놓이는 자리(소제목 바로 아래 / 첫 문단 뒤 / 섹션 끝)는 앱이 사진마다 다르게 섞는다. 원고에 따로 적지 않는다.

### 7-4. 크기
- 본문 사진은 원본 크기 그대로 올린다. 원고에서 할 일은 없다.
