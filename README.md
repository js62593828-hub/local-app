# 콘텐츠 자동화 로컬 대시보드

더블클릭으로 실행하는 로컬 웹 프로그램입니다. 터미널 명령어는 최초 설치 때만 사용합니다.

## 폴더 구성
```
local-app/
├── run.bat                 ← 이거 더블클릭하면 실행됩니다
├── app.py                  ← 웹 서버 (Flask)
├── main.py                 ← 1단계: 키워드/시즌 캘린더 엔진 (주차 단위 30개 생성)
├── naver_api.py             ← 네이버 검색광고 API 연동
├── scorer.py                 ← 키워드 점수 매기기
├── config.py                  ← 네이버 API 키 환경변수 로딩
├── content_parser.py           ← 붙여넣은 글을 제목/플랫폼별로 자동 분리
├── seo_formatter.py             ← SEO 규칙 (표 변환, 강조, 구조화 데이터, 목차, 네이버 태그)
├── image_gen.py                  ← GPT Image mini 이미지 생성 + 합성
├── seasonal_calendar.json         ← 월별 시즌 키워드 캘린더 (직접 수정 가능)
├── requirements.txt                ← 필요한 파이썬 패키지
├── fonts/Pretendard-Medium.otf       ← 이미지에 쓰이는 한글 폰트 (번들 포함)
└── templates/
    ├── index.html                     ← 대시보드 화면 (주차별 키워드, 승인/발행 체크박스)
    ├── article_edit.html               ← 편집기 화면
    └── final_view.html                  ← 플랫폼별 최종본 전용 페이지
```

## 처음 설치 (한 번만)

### 1) 파이썬 설치
https://www.python.org/downloads/ 에서 설치, **"Add python.exe to PATH" 꼭 체크**

### 2) 이 폴더 전체를 원하는 위치에 저장
압축을 풀어서 `local-app` 폴더 전체(하위 폴더 `fonts`, `templates` 포함)를 그대로 저장하세요.
구글드라이브 등 클라우드 동기화 폴더 안에 두면 여러 컴퓨터에서 이어서 쓸 수 있습니다.

### 3) API 키 등록 (시스템 환경 변수)
시작 메뉴 → "환경 변수" 검색 → 시스템 환경 변수 편집 → 환경 변수 → 사용자 변수에 추가:

| 변수 이름 | 값 |
|---|---|
| `NAVER_CUSTOMER_ID` | 네이버 검색광고에서 발급받은 값 |
| `NAVER_API_KEY` | 네이버 검색광고 액세스라이선스 |
| `NAVER_SECRET_KEY` | 네이버 검색광고 비밀키 |
| `OPENAI_API_KEY` | (선택) GPT Image mini 실제 이미지 생성용, https://platform.openai.com 에서 발급 (조직 인증 필요할 수 있음) |

키가 없어도 실행은 되고, 자동으로 "목(mock) 모드"로 가짜 데이터/이미지를 사용합니다.

### 4) 바탕화면 바로가기 만들기 (추천)
`run.bat` 우클릭 → 바로 가기 만들기 → 바탕화면으로 이동. 이후엔 이 아이콘만 더블클릭하면 됩니다.

## 매번 사용하는 방법
1. `run.bat` 더블클릭 (또는 바탕화면 바로가기)
2. 브라우저가 자동으로 열리며 대시보드 화면 표시
3. 상단에서 원하는 주차 선택 (이전/다음 주 이동, 드롭다운)
4. **[이번 주 키워드 새로 불러오기]** → 키워드 30개 목록 (이미 승인 체크된 항목은 유지된 채 나머지만 새로 채워짐)
5. 원하는 키워드 **승인 체크박스** 클릭 → **[편집기로 →]** 링크 클릭
6. ① 시작 프롬프트로 클로드에게 받은 결과 전체를 통째로 붙여넣기 → 자동 분리 확인
7. ② 이미지 일괄 생성 (본문 6장 + 표지 3장 + 인스타 카드 6장)
8. ③ 플랫폼마다 원하는 제목/표지 조합 선택
9. ④ 플랫폼별 콘텐츠 생성 → 각 플랫폼 "최종본 보기" 링크로 전용 페이지 이동 → [전체 복사]로 붙여넣기
10. 발행 완료하면 최종본 페이지의 [발행완료] 버튼, 또는 대시보드의 발행 체크박스로 표시

## 글쓰기 시작 프롬프트
별도로 드린 `글쓰기_시작프롬프트.md` 파일 내용을 새 채팅에 붙여넣고 키워드만 채워서 사용하세요.
클로드가 `[제목후보]`, `[플랫폼:워드프레스]` 같은 표시를 정확히 넣어줘야 자동 분리가 됩니다.

## 자주 있는 문제
- **"ModuleNotFoundError"**: `python -m pip install -r requirements.txt` 실행
- **"TemplateNotFound"**: `templates` 폴더가 `app.py`와 같은 위치에 있는지, 그 안에 필요한 html 파일이 있는지 확인
- **한글이 네모로 깨짐**: `fonts/Pretendard-Medium.otf` 파일이 제자리에 있는지 확인
- **분리 실패**: 클로드 응답에 `[제목후보]`, `[플랫폼:이름]` 표시가 정확히 있는지, 코드블록(```)째로 복사했는지 확인

## 네이버 검색결과 구조 수집 (스마트블록·관련 검색어)
키워드 하나를 네이버에서 검색해서 **스마트블록 제목, 관련 검색어, 광고·쇼핑·이미지 영역 유무**를 JSON 파일로 저장합니다.
ego lite 브라우저가 잠깐 열려 검색하고, 끝나면 그 창을 스스로 닫습니다. 앱 데이터(글 목록 등)는 전혀 건드리지 않습니다.

**준비물**: ego lite 설치(이미 되어 있음), 파이썬. API 키나 비용은 없습니다.

### 실행 방법 (둘 중 하나)
1. **더블클릭**: 이 폴더의 `naver_serp_collect.bat` 더블클릭 → "검색할 키워드를 입력하세요"에 키워드 입력 → Enter
2. **명령어**: 이 폴더에서
   ```
   python tools/naver_serp_collect.py 캠핑 의자 추천
   ```
   - 키워드에 `&` 같은 특수문자가 있으면 큰따옴표로 감싸세요: `python tools/naver_serp_collect.py "A&B 추천"`
   - 화면에만 보고 저장은 안 하려면 끝에 `--no-save`
   - 저장 위치를 직접 정하려면 `--out 경로.json`

### 결과 파일
- 저장 위치: `serp_collect/날짜_시각_키워드.json` (예: `serp_collect/20261108_153914_캠핑_의자_추천.json`)
- 실행 한 번에 약 20~30초 걸립니다.

| 항목 | 뜻 |
|---|---|
| `keyword` | 검색한 키워드 |
| `collected_at` | 수집 시각 (한국 시간) |
| `smart_blocks` | 스마트블록 제목 목록 |
| `related_keywords` | 관련 검색어 목록 |
| `has_ad` | 광고 영역이 있으면 `true` (파워링크, 브랜드 콘텐츠 포함) |
| `has_shopping` | 쇼핑 영역(가격비교, 플러스 스토어 등)이 있으면 `true` |
| `has_image` | 이미지 영역이 있으면 `true` |
| `has_ai_briefing` | 네이버 AI 브리핑(AI 요약)이 있으면 `true`. AI 브리핑은 스마트블록 목록에 넣지 않습니다 |
| `ai_briefing_sources` | AI 브리핑이 인용한 출처 글 목록 (`title` 글 제목, `url` 주소). 광고 링크는 뺍니다 |
| `sections` | 화면에 나온 모든 영역을 위에서부터 순서대로 (제목 + 종류). 분류가 맞는지 눈으로 확인할 때 보세요 |
| `url` | 실제로 검색한 주소 |

### 알아둘 점
- **스마트블록 판별 방식**: 제목이 붙은 영역 중에서 광고·쇼핑·이미지·관련 검색어와 네이버 기본 영역(블로그, 카페, 인플루언서, 네이버 클립, 관련질문, 지식iN 등)을 뺀 나머지를 스마트블록으로 봅니다. 네이버가 새 기본 영역을 만들면 스마트블록으로 잘못 잡힐 수 있으니, 이상하면 `sections`를 확인하세요.
- 같은 키워드도 **시간대·로그인 상태에 따라** 결과가 달라질 수 있습니다.
- 네이버 화면 구조가 바뀌면 수집이 실패하거나 빈 목록이 나올 수 있습니다. 그때는 클로드에게 "naver_serp_collect 고쳐줘"라고 요청하세요.
- "[실패] ego-browser 를 찾을 수 없습니다"가 나오면 ego lite가 설치·실행되어 있는지 확인하세요.

## 여러 키워드 한꺼번에 수집 (collect_serp.py, 순수 JSON 출력)
위 수집기와 같은 방식으로 검색하되, **키워드 목록 파일을 받아 순서대로 처리**하고 결과를 **JSON만** 내보냅니다.
클로드 없이 파이썬과 ego lite만으로 돌아갑니다. 앱 데이터는 건드리지 않습니다.

### 1) 키워드 목록 파일 만들기
메모장으로 `.txt` 파일을 만들고 **한 줄에 키워드 하나**씩 적습니다. (예시: `tools/serp_keywords_example.txt`)
```
# 이렇게 #으로 시작하는 줄과 빈 줄은 무시됩니다
캠핑 의자 추천
겨울 패딩 세탁
```
- 저장할 때 인코딩은 **UTF-8** 권장 (메모장 'ANSI'로 저장해도 읽힙니다)
- 같은 키워드가 두 번 있으면 한 번만 수집합니다

### 2) 실행 (PowerShell에서, 이 폴더 위치에서)
| 하고 싶은 것 | 명령어 |
|---|---|
| 목록 파일 전체 수집 → 파일로 저장 **(추천)** | `python tools\collect_serp.py --file 목록.txt --out 결과.json` |
| 키워드 1개만 수집 | `python tools\collect_serp.py 캠핑 의자 추천` |
| 영역 전체 목록·주소까지 포함 | 끝에 `--detail` 추가 |
| 키워드 사이 쉬는 시간 바꾸기 (기본 3초) | 끝에 `--delay 5` 추가 |

- 키워드 1개당 약 15~30초 걸립니다. 진행 상황(`[1/10] 수집 중: ...`)은 화면에 따로 표시되고, 결과 JSON에는 섞이지 않습니다.
- **결과 저장은 꼭 `--out`으로 하세요.** PowerShell의 `> 결과.json`으로 저장하면 한글이 깨지거나 다른 형식(UTF-16)으로 저장될 수 있습니다.

### 3) 결과 모양
- 키워드 1개로 실행하면 `{ ... }` 하나, 목록 파일로 실행하면 `[ {...}, {...} ]` 목록으로 나옵니다.

| 항목 | 뜻 |
|---|---|
| `keyword` | 검색한 키워드 |
| `collected_at` | 수집 시각 (한국 시간) |
| `smart_blocks` | 스마트블록 제목 목록 |
| `related_keywords` | 관련 검색어 목록 |
| `has_ad` / `has_shopping` / `has_image` | 광고 / 쇼핑 / 이미지 영역이 있으면 `true` |
| `has_ai_briefing` | 네이버 AI 브리핑이 있으면 `true` (AI 브리핑은 `smart_blocks`에 넣지 않음) |
| `ai_briefing_sources` | AI 브리핑이 인용한 출처 글 `[{"title": 글 제목, "url": 주소}, ...]`. 없으면 `[]` |
| `error` | (실패한 키워드에만) 실패 이유. 하나가 실패해도 나머지는 계속 수집합니다 |
| `sections`, `url` | `--detail`을 붙였을 때만 나옵니다 |

- 끝나면 `[완료] 성공 N개 / 실패 M개`가 표시됩니다. 하나라도 실패하면 종료 코드가 1입니다(자동화용).
- 목록이 길 때 중간에 **Ctrl+C**로 멈추면 그때까지 모은 결과만 출력·저장하고 끝납니다.
- 스마트블록 판별 방식과 주의점은 위 "알아둘 점"과 같습니다.

## 키워드 지표 수집 (collect_metrics.py, 순수 JSON 출력)
씨앗 키워드마다 **연관 키워드**를 받아 월간 검색량·블로그 문서 수·포화도·12개월 추세를 JSON으로 모읍니다.
클로드 없이 파이썬만으로 돌아가고, 네이버 API는 무료입니다. 앱 데이터는 건드리지 않습니다.

### 준비물
- 이 폴더의 `.env` 파일에 있는 네이버 키를 그대로 씁니다. **키 값은 화면이나 결과 파일에 나오지 않습니다.**

| 지표 | 쓰는 API | .env 이름 |
|---|---|---|
| 월간 검색량 | 네이버 검색광고 | `NAVER_CUSTOMER_ID`, `NAVER_API_KEY`, `NAVER_SECRET_KEY` |
| 블로그 문서 수 | 블로그 검색 | 아래 키 중 **되는 것을 자동으로** 씀 |
| 12개월 추세 | 데이터랩 검색어트렌드 | 〃 |

- 블로그 검색과 데이터랩은 ① `NAVER_SEARCH_CLIENT_ID/SECRET` → ② 네이버 API 허브 `NAVER_HUB_CLIENT_ID/SECRET` → ③ 개발자센터 `NAVER_LOGIN_CLIENT_ID/SECRET` 순서로 시도합니다.
- 그 API가 꺼져 있으면 그 칸만 `null`로 비우고 계속 진행합니다. 이유는 결과의 `api_status`에 적힙니다.

### 실행 (PowerShell, 이 폴더에서)
1. 씨앗 키워드 목록 파일을 만듭니다. 한 줄에 하나씩 적고, `#`으로 시작하는 줄과 빈 줄은 무시됩니다. (예시: `tools/metrics_seeds_example.txt`)
2. 아래 명령어를 실행합니다.

| 하고 싶은 것 | 명령어 |
|---|---|
| 목록 파일 수집 → 파일로 저장 **(추천)** | `python tools\collect_metrics.py --file 씨앗.txt --out 지표.json` |
| 씨앗 1개만 | `python tools\collect_metrics.py 패딩 세탁` |
| 씨앗마다 연관 키워드 수 바꾸기 (기본 30, 검색량 많은 순) | 끝에 `--max-related 50` 추가 |

- 결과 저장은 꼭 `--out`으로 하세요. PowerShell의 `>`로 저장하면 한글이 깨질 수 있습니다.
- 데이터랩은 하루 1,000번까지 부를 수 있습니다. 키워드 5개를 한 번에 묻기 때문에 키워드 약 5,000개까지 됩니다. 블로그 검색은 하루 25,000번까지입니다.

### 결과 모양
| 항목 | 뜻 |
|---|---|
| `collected_at` | 수집 시각 (한국 시간) |
| `trend_months` | 추세에 쓴 12개월 (이번 달은 아직 안 끝나서 빼고, 지난달까지) |
| `api_status` | API별 상태. `ok (hub)` = 허브 키로 성공, `unavailable: ...` = 못 씀(이유) |
| `seeds[].seed` / `related_total` | 씨앗 키워드 / 네이버가 준 연관 키워드 전체 개수 |
| `keywords[].keyword` | 연관 키워드 (씨앗 자신이 맨 앞) |
| `monthly_pc` / `monthly_mobile` / `monthly_total` | 최근 한 달 검색량 PC / 모바일 / 합계. 네이버가 "10 미만"으로 주면 5로 적습니다 |
| `blog_docs` | 블로그 문서 수 (못 구하면 `null`) |
| `saturation` | 포화도 = 문서 수 ÷ 검색량 합계. **클수록 경쟁이 심함** (못 구하면 `null`) |
| `trend_12m` | 월별 추세 `[{"month": "2025-11", "ratio": 81.2}, ...]`. 그 키워드에서 가장 많이 검색된 달이 100 |

## 키워드 발굴 한 번에 돌리기 (run_pipeline.py)
지표 수집 → 필터 → 네이버 화면 수집 → 100점 채점을 **한 번에** 돕니다. 앱 데이터는 건드리지 않고, 결과는 `pipeline/` 폴더에만 저장됩니다.

### 실행 (PowerShell, 이 폴더에서)
```
python tools\run_pipeline.py --file 씨앗.txt
```
- 씨앗 1개만: `python tools\run_pipeline.py 패딩 세탁`
- 시험 삼아 작게 돌리기: 끝에 `--max-related 30 --max-serp 3` (이번 한 번만 `filter.json` 숫자를 덮어씁니다)
- 화면 수집이 키워드당 15~30초 걸려서, 기본값(최대 30개)이면 10분쯤 걸립니다.

### 씨앗 파일에 핵심 단어 지정하기
한 줄을 `씨앗 | 핵심단어1, 핵심단어2` 로 쓰면, **핵심 단어가 모두 들어간 키워드만** 통과합니다 (이때는 `seed_word_mode`를 무시). `|` 가 없으면 `seed_word_mode` 설정대로 합니다.
```
패딩 세탁 | 패딩
캠핑 의자 | 캠핑, 의자
```
- 키워드 하나를 직접 입력할 때는 `|` 때문에 따옴표가 필요합니다: `python tools\run_pipeline.py "패딩 세탁 | 패딩"`

### 숫자 바꾸기: `tools/filter.json`
메모장으로 열어 숫자·단어만 바꾸고 저장하면 됩니다.

| 항목 | 기본값 | 뜻 |
|---|---|---|
| `volume_min` / `volume_max` | 300 / 3000 | 월간 검색량 범위 |
| `saturation_keep_ratio` | 0.3 | 같은 씨앗 안에서 포화도가 낮은 쪽 30%만 통과 |
| `require_seed_word` | true | 씨앗 단어 검사를 할지 (false 면 검사 안 함) |
| `seed_word_mode` | "any" | `"any"` = 씨앗 단어 중 **하나 이상** 포함, `"all"` = **모두** 포함 |
| `exclude_words` | 쿠팡, 중고 … | 이 단어가 들어 있으면 제외 (자유롭게 추가) |
| `max_related_per_seed` | 100 | 씨앗당 연관 키워드 최대 수 |
| `max_serp_keywords` | 30 | 화면 수집할 키워드 최대 수 |
| `cache_days` | 30 | 같은 키워드를 다시 수집하지 않는 기간 |
| `score_weights` | 수요 25 / 포화도 20 / 화면 35 / 내 적합도 20 | 배점 |
| `screen_weights` | 스마트블록 15 / 광고 8 / 쇼핑 6 / AI브리핑없음 6 | 화면 점수 안의 비중 |

### 점수 계산 (100점)
1. **수요 25**: 검색량(범위 안에서 높을수록, 60%) + 12개월 추세(최근 3개월이 이전 9개월보다 늘수록, 40%)
2. **포화도 20**: 같은 씨앗 안에서 포화도가 가장 낮은 키워드가 만점, 높을수록 감점
3. **화면 기회 35**: 스마트블록이 있으면 가점, 광고·쇼핑 영역이 적을수록 가점, AI 브리핑이 없으면 가점
4. **내 적합도 20**: 지금은 전부 0점. 나중에 `pipeline/my_fit.json`에 `{"키워드": 0~100}` 형식으로 직접 적으면 반영됩니다

### 결과 파일 (`pipeline/`)
| 파일 | 내용 |
|---|---|
| `result_날짜_시각.json` | 전체 결과 (후보 전부의 지표·필터 결과·화면·점수, 사용한 설정) |
| `top10.json` | 점수 상위 10개만 |
| `cache.json` | 30일 캐시 (지우면 전부 다시 수집) |

### 알아둘 점
- 연관 키워드 100개는 **기본 필터(씨앗 단어·제외 단어·검색량 범위)를 통과한 것 중** 검색량 많은 순으로 고릅니다. 먼저 100개를 자르면 범위 밖 키워드로 자리가 차기 때문입니다.
- 화면 수집 대상은 (수요+포화도+적합도) 점수가 높은 순으로 고릅니다. 화면 점수는 수집한 키워드에만 매겨집니다.
- 블로그 검색이 안 되면 포화도 필터는 건너뜁니다. 이유는 결과의 `api_status`에 적힙니다.

### 옛 방식 (참고용 — 더 이상 실행하지 않음)
`run_weekly.bat` 과 `tools/run_weekly.py` 는 `archive/old_features/` 로 옮겼습니다. 아래 설명에서 run_weekly.bat 으로 실행하는 부분은 지금은 동작하지 않고, make_seeds.py·plan_posts.py 등 개별 도구는 tools/ 에 그대로 있습니다.
매주 한 번 돌려서 **다음 주 월~일 원고 기획**을 만듭니다. (실행일이 일요일이면 내일이 월요일, 금요일이면 3일 뒤가 월요일)

```
(옛 방식) archive/old_features/run_weekly.bat  ← 옮겨 둠, 실행 안 함
```
순서: ① `existing_posts.py`(이미 발행·예약된 글 키워드 수집) → ② `make_seeds.py`(이번 주 씨앗 자동 생성) → ③ `run_pipeline.py`(지표 수집 → 필터 → 화면 수집 최대 60개 → 채점) → ④ `plan_posts.py`(일정 배정 + Claude 기획).
(②에서 Claude 호출이 실패하면 지난주 씨앗을 그대로 쓰고 계속 진행합니다. ①은 세 곳(워드프레스 2곳·네이버 RSS)이 **모두** 실패하면 중단합니다.)
**한 단계가 실패하면 다음 단계는 실행하지 않고**, 진행·오류 기록을 `pipeline/log_날짜.txt`에 남깁니다.
(파이썬을 못 찾으면 `pipeline/log_fatal.txt`에 남습니다. 창이 바로 닫히니 결과는 로그 파일로 확인하세요.)

### 1) 주제 설정: `tools/topic.json`
공통 주제 범위(생활 살림·집 관리), 카테고리 10개, 플랫폼 역할(네이버 = 생활 문제 해결형 / 워드프레스 = 제품 선택형), 우선 단어, 금지 주제가 들어 있습니다. 메모장으로 고칠 수 있습니다.

### 2) 씨앗 파일: `tools/weekly_seeds.txt` (자동 생성)
`make_seeds.py`가 **매주 새로 만들어 덮어씁니다.** 한 줄 = `씨앗 | 핵심단어`.
- 만드는 재료: topic.json의 카테고리, 다음 주 계절, 카테고리 단어의 네이버 검색광고 연관 키워드, 지난 `ranking.json`의 씨앗별 성과, 기존 발행 글 제목.
- 15~20개, 카테고리가 고루 섞이게, 성과 좋은 씨앗 약 60% 유지 + 새 씨앗 약 40%.
- 이전 파일은 `tools/weekly_seeds.20261108.txt`처럼 날짜를 붙여 보관하고, 고른 이유는 `pipeline/seeds_log_날짜.json`에 남습니다(사용량 포함).
- 실패하면 파일을 바꾸지 않아 **지난주 씨앗을 그대로 씁니다.** 손으로 씨앗을 넣고 싶으면 이 단계 없이 `python tools\run_pipeline.py --file 내씨앗.txt`로 따로 돌리세요.
- 단독 실행: `python tools\make_seeds.py` (Claude sonnet 1번, 약 $0.08)

### 3) 기존 발행 글 키워드: `pipeline/existing_keywords.json`
`existing_posts.py`가 워드프레스(.env에 설정된 사이트 전부: 롱텀·숍)에서 **발행·예약 글 제목**을, 네이버 블로그 RSS에서 **최근 글 제목**(약 50개)을 모읍니다. `plan_posts.py`는 지난주 기획뿐 아니라 이 목록과도 겹치는 키워드를 뺍니다(기존 글 제목에 키워드가 들어 있거나 거의 같으면 제외).
- 워드프레스 **포커스 키워드는 REST로 읽히지 않아** 제목만 모읍니다.
- **누적 저장**: 실행할 때마다 이 파일에 이어서 쌓습니다. RSS(최근 약 50개)에서 빠진 옛 글도 계속 남고, 글마다 처음 본 날(`first_seen`)과 마지막으로 본 날(`last_seen`)이 적힙니다. (사이트에서 글을 지워도 목록에서는 안 지워집니다.)
- **네이버 전체 글 채우기**: 처음 한 번은 로그인 없이 보이는 공개 글 목록(`PostTitleListAsync`)에서 전체 글 제목을 가져옵니다(브라우저 불필요). 끝나면 `naver_backfill.done`이 기록되어 다음부터는 RSS만 씁니다. 다시 전체를 채우고 싶으면 `python tools\existing_posts.py --backfill-naver`
- **앱 대기열(아직 발행 안 된 키워드)도 읽습니다.** `content_queue*.json`에서 **승인됐거나 직접 추가한** 항목 중, 짝이 되는 글 장부(`articles*.json`)에 발행 기록이 없는 키워드를 겹침 검사에 넣습니다. 승인 안 된 주간 후보 목록은 "등록"으로 보지 않습니다. 앱 장부는 **읽기만 하고 수정하지 않습니다.** 이 항목은 누적하지 않고 매번 현재 상태로 바꿉니다(발행되면 빠지도록).
- 단독 실행: `python tools\existing_posts.py`

### 4) 발행량·옵션: `tools/filter.json`의 `weekly` 부분
| 항목 | 기본값 | 뜻 |
|---|---|---|
| `posts_per_day` | 네이버 3 / 워드프레스 2 | **플랫폼별 하루 편수** (주 35편). 숫자만 바꾸면 됩니다 |
| `reserve_count` | 10 | 예비 기획 수 (기획은 35 + 10 = 45개) |
| `max_serp_keywords` | 60 | 화면 수집 최대 수 (60개면 20분쯤 걸림) |
| `claude_batch_size` | 10 | Claude를 한 번에 몇 개씩 부를지 (45개면 5번) |
| `similarity_threshold` | 0.75 | 이 이상 비슷하면 "거의 같은 키워드" (낮추면 더 엄격) |
| `avoid_past_weeks` | 1 | 지난 몇 주 기획과 겹치지 않게 할지 |

### 5) 배정 규칙
1. **네이버**: topic.json의 **해결형 단어**(제거·청소법·하는 법·주기·방지·원인)가 들어간 키워드를 먼저, 그 안에서 화면 기회 점수가 높은 순.
2. **워드프레스**: **제품 선택형 단어**(단점·장단점·종류·고르는 법·후기분석·비교)가 들어간 키워드를 먼저, 그 안에서 추세가 꾸준한 순. (예전의 "상업 단어 제외" 규칙은 없앴습니다.)
3. 같은 키워드, 거의 같은 키워드는 두 플랫폼에 겹치지 않게 하고, **지난주 기획(`plan_지난주월요일.json`)과 기존 발행·예약 글(`existing_keywords.json`)과도** 겹치지 않게 합니다.
4. **의도 중복 제외는 분류 단계 결과를 씁니다**: 같은 글이 될 키워드 묶음은 `run_pipeline.py`의 유형 분류 호출에서 함께 받아 `ranking.json`의 `intent_groups`에 들어 있고, 여기서는 묶음마다 **점수가 가장 높은 1개만** 남기고 나머지는 결과 파일의 `excluded_intent_duplicates`에 "의도 중복으로 제외"로 기록합니다. 이제 `plan_posts.py`는 이 목적의 Claude 호출을 하지 않습니다(`--intent-only` 삭제). `intent_groups`가 없는 옛 `ranking.json`이면 이 단계를 건너뛰고 `problems`에 적습니다.
5. **유형 표시 반영**: 분류에서 해결·정보형(문제 해결·방법·원인·종류·특징·습성·서식지·주기·차이 등)은 네이버 후보, 제품선택형은 워드프레스 후보로 표시되고(`platform_hint`), 배정 때 맞는 쪽을 먼저 씁니다(후보가 모자랄 때만 반대편 사용).
5. 우선순위가 높은 것부터 월·화·수… 순으로 날짜에 퍼뜨립니다. 예비는 날짜 없이 `role: reserve`로 들어갑니다.
6. 후보가 모자라면 그만큼 비워 두고 `shortage`에 몇 개 모자란지 적습니다.

### 6) 결과: `pipeline/plan_다음주월요일날짜.json` (예: `plan_20261116.json`)
| 항목 | 내용 |
|---|---|
| `schedule` | 한눈에 보는 일정 (날짜, 요일, 플랫폼, 키워드) |
| `plans` | 기획마다 플랫폼·발행일·요일·점수·검색 의도·놓친 빈칸·제목 후보 3개·소제목 4~5개·내 경험 자리 |
| `usage` | **Claude 전체 사용량 합계**(`total_cost_usd`, 토큰, 호출 수)와 호출별 내역 |
| `shortage` / `excluded_overlap_with_past` / `problems` | 모자란 수 / 지난주와 겹쳐 뺀 키워드 / 확인할 점 |

- Claude에게는 키워드별 요약(검색량, 포화도, 스마트블록 제목, 관련 검색어, 점수, 플랫폼)만 보냅니다. 상위 글 본문은 보내지 않으므로 "놓친 빈칸"은 화면 구성에서 **추정한 것**입니다.
- 같은 주에 다시 돌리면 이전 파일은 `plan_날짜.old_시각.json`으로 이름이 바뀌어 보관됩니다.
- 기획 45개를 Claude 5번으로 만들면 한 번에 몇백 원 수준입니다(정확한 값은 결과의 `usage.total_cost_usd`).
- 일부만 직접 돌릴 때: `python tools\plan_posts.py` (이미 만들어진 `pipeline/ranking.json`으로 기획만 다시)

- **시험용 기준일** (옛 방식): `run_weekly.bat --today 2026-11-13`처럼 주면 "다음 주 월요일"을 그 날짜 기준으로 계산합니다(씨앗 생성의 계절 판단과 글 기획에 같이 적용).

   - **시작 위치(옵션)**: `G:\내 드라이브\DataBase\local-app` (큰따옴표 없이)
   - **확인**을 누릅니다.
6. **[조건] 탭**: "이 작업을 실행하기 위해 절전 모드 종료"에 체크합니다. 노트북이면 "컴퓨터의 AC 전원이 켜져 있는 경우에만 작업 시작"은 체크를 해제합니다.
7. **[설정] 탭**: **"예약된 시작 시간을 놓친 경우 가능한 한 빨리 작업 시작"에 체크**합니다. (금요일 밤 9시에 PC가 꺼져 있었다면, 켜지는 대로 바로 실행됩니다.) 필요하면 "작업이 실패하면 다시 시작 간격"도 켜 둘 수 있습니다.
8. **확인**을 누르면 Windows 비밀번호를 물을 수 있습니다. 입력하면 등록이 끝납니다.
9. **시험**: 작업 목록에서 `주간 원고 기획`을 오른쪽 클릭 → **실행**. 20~30분 뒤 `pipeline/log_오늘날짜.txt`에 "정상 종료"가 적혀 있고 `pipeline/plan_…json`이 생기면 성공입니다.
- 금요일 밤 9시에는 PC가 켜져 있고 구글 드라이브(G:)가 연결되어 있어야 합니다.
- 씨앗(`weekly_seeds.txt`)을 바꾸고 싶으면 파일만 고치면 되고, 작업 스케줄러는 다시 만들 필요가 없습니다.

## 키워드 유형 분류 (run_pipeline.py, 화면 수집 전)
필터 통과 키워드의 **글자만** Claude(sonnet, 1단계, 도구 끔)에 **한 번** 보내 유형과 의도 묶음을 함께 받습니다 (`tools/keyword_classify.py`).
- 유형: 해결·정보형 / 제품선택형 / 브랜드모델구매 / 지역업체 / 기타. 브랜드 키워드라도 "단점·후기·비교"가 붙으면 제품선택형.
- **브랜드모델구매·지역업체는 화면 수집에서 제외**합니다. 해결·정보형=네이버 후보, 제품선택형=워드프레스 후보로 표시합니다.
- 결과 파일(`result_*.json`)의 `classification`에 유형별 개수·제외 목록(사유 포함)·의도 묶음·사용량이 기록되고, 각 키워드에 `kw_type`/`platform_hint`/`intent_group`/`exclude_reason`이 붙습니다.
- 호출이 실패하면 분류 없이(제외 없이) 계속 진행하고 `classification.status`가 `failed`로 남습니다. 건너뛰려면 `--no-classify`.
