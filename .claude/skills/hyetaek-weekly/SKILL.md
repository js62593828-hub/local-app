# 혜택주간 — W혜택주머니 주간 자동 진행

## 0. 시작 전에 (매번)
1. CLAUDE.md 규칙을 따른다(git 상태 확인, 데이터 파일 백업, 쉬운 말 보고, 한국어).
2. 아래 규칙 파일을 읽는다. **원고를 쓰기 직전마다 원고지침을 다시 읽는다.**
   - `docs/혜택주머니/기획지침_자동.md` (흐름·기획 규칙)
   - `docs/혜택주머니/원고지침_혜택주머니.md` (원고 형식·금지 — 원본)
   - `docs/혜택주머니/제목클릭규칙.md`, `docs/혜택주머니/글뼈대규칙.md`, `docs/혜택주머니/시즌달력_10-12월.md`, `docs/혜택주머니/시즌달력_월별/` (월별 한 줄 기록 — 내년 같은 시기 참고)
   - `docs/혜택주머니/실적학습.md` **최근 4주분**(맨 위 4칸) — 1단계를 시작하기 전에 읽는다(8차).
3. 주차 = 사용자가 말한 주의 월요일(YYYY-MM-DD). 작업 폴더 = `주간기획/혜택_YYYY-MM-DD/` (없으면 만든다).
4. HANDOFF.md 맨 위에 "진행 중: 혜택주간 YYYY-MM-DD, n단계" 3줄을 적고, 단계가 끝날 때마다 고친다.

## 1. 실적 분석 → 글 장부 → 성적표 (8차 개편)
먼저 `docs/혜택주머니/실적학습.md` 최근 4주분을 읽는다. 그다음 **이 순서로** 돌린다(서치콘솔·워드프레스·앱 글 데이터는 읽기만, 새 파일만 만든다).
```
python tools/lt_perf_report.py --week YYYY-MM-DD
python tools/lt_ledger.py --all
python tools/lt_learn.py --week YYYY-MM-DD
```
- `lt_perf_report`: 서치콘솔에서 일별(page×date)과 28일 검색어 전부(page×query)를 받아 `주간기획/_누적/perf_daily.json`(날짜별로 합침, 같은 날짜는 새 값으로 교체)·`_누적/queries/주.json`에 쌓고, `작업폴더/01_실적분석.md`(① 최근 7일 vs 그 전 7일 ② 글마다 발행 후 7·14·28일 ③ 지난주 글은 색인·첫 노출일만)를 만든다. 서치콘솔 주소를 글에 맞춘 결과는 `_누적/주소맞춤.json`(못 맞춘 목록 포함). 못 맞춘 주소 중 사람이 아는 것은 `_누적/주소맞춤_수동.json` 에 적는다.
- `lt_ledger --all`: 빠진 글을 장부(`_누적/글장부.json`)에 채운다(다시 돌려도 중복 없음). 지난 주 기획 보충 파일 `06_확정_장부.json` 이 있으면 대상·시의성 종류·관련 날짜가 채워진다.
- `lt_learn`: 장부 × 일별 실적 → `작업폴더/01b_성적표.md`(발행 후 14일·28일 기준, 같은 순위 구간끼리 비교, 8편 미만 칸은 참고, 이미 문 앞 키워드, 빗나간 판정, 갱신 전후). 숫자만 쓰고 결론 문장은 없다.
- 서치콘솔 받기가 실패하면 저장본으로 하고 "몇 월 며칠 자료"인지 적는다(도구가 맨 위에 적는다).
- **읽고 정리(01_실적분석.md + 01b_성적표.md)**: 잘된 글 3 · 안 된 글 3(14·28일 기준) · 왜 그런지(제목 장치·대상 좁힘·시의성·뼈대) · 지난 주 가설의 결과 · 이번 주에 반영할 점 3줄 · 갱신 후보.
- **끝에 `docs/혜택주머니/실적학습.md` 맨 위에 한 칸 추가**: 날짜 / 이번 주 발견 3줄(숫자 근거) / 지난 기획 "반영한 점"의 결과 / 다음 주 시험할 것 1~2개 / `방향:` 한 줄. 같은 방향이 3주 이어지면 성적표에 "규칙 제안 후보"로 표시된다 — **기획지침 파일은 사용자 확인 뒤에만 고친다.**

## 2. 키워드 발굴 (1-A)
1. 앱의 기획 자료를 만든다: `python tools/lt_export_plan.py --week YYYY-MM-DD` → `Claude outputs/longterm_plan_input.md`.
2. **발굴 맨 앞(8차)** — 웹 검색 전에 이 세 가지를 먼저 본다:
   ① **이미 문 앞 키워드** = `01b_성적표.md` 의 표(검색어 노출 20+·순위 8~30인데 제목·키워드로 쓴 글 없음).
   ② **키워드 은행 "다시 볼 후보"**: `python tools/lt_bank.py --candidates --week YYYY-MM-DD` → `작업폴더/02a_다시볼후보.md`(안 쓴 좋은 키워드).
   ③ **시즌달력의 같은 시기 일정**: `docs/혜택주머니/시즌달력_월별/MM월.md`(지난해 같은 달 기록)와 `시즌달력_10-12월.md`.
   이 셋에서 나온 후보를 `02_발굴.md` 맨 위 "실적·은행·달력에서 온 후보" 칸에 적고, 그다음 웹 검색을 한다.
3. 웹 검색 15회 이상(검색어를 바꿔 가며): 공식 일정(지난 2주 발표 + 앞으로 3주 신청·마감·결과·지급), 사람들이 묻는 표현(실마리로만). 대상(청년·자영업자·서민)별 3개 이상, 카테고리 6개 모두에서.
4. `작업폴더/02_발굴.md`: (맨 위) 실적·은행·달력에서 온 후보 + 정책 일정표 + 정책 후보 표(8~12개) + 조회 목록.
5. 조회 목록(60~150개, 최대 200)을 `작업폴더/02_조회목록.txt`에 한 줄에 하나.

## 3. 🎯 검색량·상승세
```
python tools/lt_keyword_volume.py --in 작업폴더/02_조회목록.txt --out 작업폴더/03_검색량.json
```
- 네이버 검색광고 월검색량 + 상승세. 숫자는 이 결과만 쓴다.
- **키워드 은행(8차)**: 30일 안에 조회한 키워드는 다시 조회하지 않고 은행(`_누적/키워드은행.json`) 값을 쓴다(결과 줄에 `bank_date` 기준일이 붙고 화면에 `[은행 날짜]`로 보인다). 새로 조회한 키워드는 도구가 알아서 은행에 날짜와 함께 쌓는다. 전부 새로 보려면 `--no-bank`.

## 4. 구글 경쟁 (1-B)
(ego lite 로 구글 검색 화면을 읽는다. 키워드 사이 5~10초 쉬고, 구글이 봇 확인 화면을 띄우면 거기서 멈추고 지금까지 결과를 저장한다. 실제 브라우저 동작은 tools/lt_google_check.mjs)
```
python tools/lt_google_check.py --in 작업폴더/04_구글목록.txt --out 작업폴더/04_구글경쟁.json
```
- 대상: 기준(대표 1,000+, 세부 50+)을 넘은 대표 키워드 + 더 좁은 대안 표현. 30일 안에 구글을 확인한 키워드는 은행 값을 쓰고 브라우저를 열지 않는다(`--no-bank` 로 끔). 새로 확인한 것은 자동으로 은행에 쌓인다.
- 판정은 기획지침 6장. 관련 검색어에서 더 좁은 표현이 나오면 3·4단계를 그 표현으로 한 번 더.

## 5. 기획표 (1-C) — 여기서 멈춘다
1. 발행 칸 만들기: `python tools/lt_schedule_slots.py --week YYYY-MM-DD` → 승인 전 14칸(오전 08:21~08:41·오후 16:41~17:14 랜덤), 애드센스 승인 후에는 `--mode full`로 21칸 `작업폴더/05_발행칸.json`.
2. 기획지침 8장 순서대로 `작업폴더/05_기획표.md`를 쓰고, 화면에도 보여 준다. **8차 추가**:
   - **① 실적 요약 칸**: 잘된 글 3 · 안 된 글 3(14·28일 기준) / 지난 가설 결과(실적학습.md) / **이번 기획에 실적으로 바뀐 점 3줄**(어떤 숫자 때문에 무엇을 바꿨는지 — 예: "대표 클릭률 0.7%(15편) → 대표 제목에 대상 좁힘") / 이번 주 시험할 것 1~2개.
   - **③ 묶음표에 "실적 근거" 칸 추가**: 그 묶음을 고른 이유가 된 실적 숫자(이미 문 앞 키워드·잘된 글·갱신 전후 등). 근거가 없으면 "(근거 없음 — 새 시도)"라고 적는다.
   - 갱신 후보는 [확인] 틀에 "갱신할 글 고르기" 줄로 올린다(예약 중인 글은 후보에서 뺀다).
3. **멈추고 사용자에게 [확인] 틀을 보여 준다. 답을 받기 전에는 6단계로 가지 않는다.**
4. [확인]을 받으면 고칠 것을 반영해 `작업폴더/06_확정.json`(형식은 tools/lt_auto_input.py 설명)을 만든다. 같이 **`작업폴더/06_확정_제목.json`**(순서별 bundle·title_draft·device·skeleton)과 **`작업폴더/06_확정_장부.json`**(묶음 기호별 `시의성 종류`[발표/신청 시작/마감/결과·지급/해마다]·`관련 날짜` + 필요하면 `대상`·`의도`)을 만든다 — 글 장부가 이 파일들에서 칸을 채운다(없으면 칸이 빈다).
   형식 예: `{"week": "YYYY-MM-DD", "bundles": {"A": {"시의성 종류": "마감", "관련 날짜": "2026-12-01"}}, "posts": {"1": {"의도": "신청 절차+마감"}}}`

## 6. 원고 (Opus 5.5 — 서브에이전트 hyetaek-writer)
- 원고는 **글 1편마다 `hyetaek-writer` 서브에이전트**(model: opus = Opus 5.5)에게 맡긴다. 이 창은 Sonnet이어도 된다(수집·정리 담당).
- **쓰는 순서(11/19)**: 같은 묶음은 발행 순서대로 **차례로**(앞 글이 끝나면 다음 글 — 앞 글의 표지·본문 장면을 넘겨준다). 묶음끼리는 동시에 하되 **한 번에 작가 3~4명까지**(5시간 한도 보호). 사실 확인 에이전트도 한 번에 3개까지.
- 모든 작가에게 공통 문체(본문 격식체, 해요체는 몇 마디만)와 [확인 필요] 처리 규칙은 agent 파일에 들어 있다. 따로 톤을 지정하지 않는다. 넘길 것: 확정 기획의 그 글 줄(키워드·역할·의도·⭐제목·뼈대·발행 시각·대표글에 없는 질문), 같은 묶음에서 먼저 발행되는 글 키워드 목록, 묶음 사실 확인 메모 경로, 이미 쓴 표지·본문 장면 목록.
- 묶음 첫 글 전에 공식 자료를 실제로 열어 사실 확인(원고지침 6번 검색 상한) → `작업폴더/원고/_사실확인_묶음이름.md`에 저장, 같은 묶음 글은 이 파일을 함께 넘긴다.
- 글마다 `작업폴더/원고/NN_YYYYMMDD-HHMM_키워드.md` 하나: 코드 블록 A(본문) + 코드 블록 B(메타데이터)를 원고지침 18번 형식 그대로.
- **분량·사진 기준(11/19)**: 대표 4,000~6,000자(목표 4,500), 세부 3,600~4,800자(목표 4,000). 본문 사진 alt 4,000자 미만 4줄·이상 5줄. FAQ 3~4쌍(최대 4).
- 다 쓴 글마다 `python tools/lt_draft_check.py --week YYYY-MM-DD --file 원고파일` → 걸린 항목이 있으면 서브에이전트가 고쳐 쓴다(최대 2번). 남으면 ⚠로 기록.
- 14편을 다 쓰면 `python tools/lt_draft_check.py --week YYYY-MM-DD` 전체 표를 사용자에게 보여 준다(글자 수·사진 줄 수·해요체 비율·통과 여부). 묶음별 표지 장면 겹침도 대조한다.
- 2편 쓸 때마다 짧게 진행 상황을 알린다. 사용자에게 질문하지 않는다(⚠로 남김).
- **갱신 글(8차)**: [확인] 틀에서 고른 갱신 글은 원고 단계에서 새 글처럼 `hyetaek-writer`에게 맡겨 **수정본**을 만든다 — 바뀐 부분 + 변경 목록 + 최종 확인 날짜. 파일은 `작업폴더/갱신/글id_제목.md` 에 두고, 장부에 갱신 날짜를 적는다: `python tools/lt_ledger.py --renew 글id YYYY-MM-DD`. **예약 중인 글은 갱신하지 않는다.** 워드프레스에 반영하는 일은 사용자가 한다(Claude는 올리지 않는다). 4주 뒤 전후 성적은 `01b_성적표.md` 의 "갱신 전후"에 자동으로 나온다.

## 7. 앱 입력
1. 미리보기: `python tools/lt_auto_input.py --week YYYY-MM-DD` (아무것도 안 씀, 바뀔 목록만 보여 줌)
2. 사용자에게 미리보기 요약을 보여 주고 "넣어"를 받으면:
   `python tools/lt_auto_input.py --week YYYY-MM-DD --apply`
   - 키워드 승인·직접 추가 → 원고 붙여넣기 → 메타데이터 저장 → 이미지 일괄 생성 → 최종본 만들기 → 예약일시 저장(발행 칸 미리 채움)
   - 이미지 생성은 비용이 든다(OpenAI). 미리보기 맨 아래에 총 장수·예상 비용(어림)이 나오니 `--apply` 전에 사용자에게 알려 준다. 특정 글만: `--only 1,3`, 이미지 건너뛰기: `--skip-images`.
   - **다시 돌려도 안전(8차)**: 같은 주·같은 키워드로 이미 앱에 다 들어간 글(원고·메타데이터·최종본·예약 정보 있음)은 "이미"로 건너뛴다(처음부터 다시 하려면 `--force`).
   - **`--apply` 가 끝나면 자동으로**: 그 주 글을 글 장부에 더하고(`lt_ledger`), `09_기획표저장.md` 를 만들고 확정 묶음의 정책·날짜를 시즌달력 월별 파일에 한 줄씩 더한다(`lt_save_plan`). 1~3월 달력 파일이 없으면 빈 틀로 만든다.
3. 끝나면 사용자에게: 넣은 글 수, 실패한 글, 발행 순서표(날짜·시각·제목·최종본 주소)를 준다.
