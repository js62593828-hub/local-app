# 혜택주간 — W혜택주머니 주간 자동 진행

## 0. 시작 전에 (매번)
1. CLAUDE.md 규칙을 따른다(git 상태 확인, 데이터 파일 백업, 쉬운 말 보고, 한국어).
2. 아래 규칙 파일을 읽는다. **원고를 쓰기 직전마다 원고지침을 다시 읽는다.**
   - `docs/혜택주머니/기획지침_자동.md` (흐름·기획 규칙)
   - `docs/혜택주머니/원고지침_혜택주머니.md` (원고 형식·금지 — 원본)
   - `docs/혜택주머니/제목클릭규칙.md`, `docs/혜택주머니/글뼈대규칙.md`, `docs/혜택주머니/시즌달력_10-12월.md`
3. 주차 = 사용자가 말한 주의 월요일(YYYY-MM-DD). 작업 폴더 = `주간기획/혜택_YYYY-MM-DD/` (없으면 만든다).
4. HANDOFF.md 맨 위에 "진행 중: 혜택주간 YYYY-MM-DD, n단계" 3줄을 적고, 단계가 끝날 때마다 고친다.

## 1. 실적 분석
```
python tools/lt_perf_report.py --week YYYY-MM-DD
```
- 서치콘솔을 새로 받아(perf_tracker) `작업폴더/01_실적분석.md`를 만든다.
- 읽고 정리: 잘된 글 3 · 안 된 글 3 · 왜 그런지(제목 장치·대상 좁힘·시의성·뼈대) · 이번 주에 반영할 점 3줄 · 갱신 후보.
- 서치콘솔 받기가 실패하면 마지막 저장본으로 하고 "몇 월 며칠 자료"인지 적는다.

## 2. 키워드 발굴 (1-A)
1. 앱의 기획 자료를 만든다: `python tools/lt_export_plan.py --week YYYY-MM-DD` → `Claude outputs/longterm_plan_input.md`.
2. 웹 검색 15회 이상(검색어를 바꿔 가며): 공식 일정(지난 2주 발표 + 앞으로 3주 신청·마감·결과·지급), 사람들이 묻는 표현(실마리로만). 대상(청년·자영업자·서민)별 3개 이상, 카테고리 6개 모두에서.
3. `작업폴더/02_발굴.md`: 정책 일정표 + 정책 후보 표(8~12개) + 조회 목록.
4. 조회 목록(60~150개, 최대 200)을 `작업폴더/02_조회목록.txt`에 한 줄에 하나.

## 3. 🎯 검색량·상승세
```
python tools/lt_keyword_volume.py --in 작업폴더/02_조회목록.txt --out 작업폴더/03_검색량.json
```
- 네이버 검색광고 월검색량 + 상승세. 숫자는 이 결과만 쓴다.

## 4. 구글 경쟁 (1-B)
(ego lite 로 구글 검색 화면을 읽는다. 키워드 사이 5~10초 쉬고, 구글이 봇 확인 화면을 띄우면 거기서 멈추고 지금까지 결과를 저장한다. 실제 브라우저 동작은 tools/lt_google_check.mjs)
```
python tools/lt_google_check.py --in 작업폴더/04_구글목록.txt --out 작업폴더/04_구글경쟁.json
```
- 대상: 기준(대표 1,000+, 세부 50+)을 넘은 대표 키워드 + 더 좁은 대안 표현.
- 판정은 기획지침 6장. 관련 검색어에서 더 좁은 표현이 나오면 3·4단계를 그 표현으로 한 번 더.

## 5. 기획표 (1-C) — 여기서 멈춘다
1. 발행 칸 만들기: `python tools/lt_schedule_slots.py --week YYYY-MM-DD` → 21칸(랜덤 시각) `작업폴더/05_발행칸.json`.
2. 기획지침 8장 순서대로 `작업폴더/05_기획표.md`를 쓰고, 화면에도 보여 준다.
3. **멈추고 사용자에게 [확인] 틀을 보여 준다. 답을 받기 전에는 6단계로 가지 않는다.**
4. [확인]을 받으면 고칠 것을 반영해 `작업폴더/06_확정.json`(형식은 tools/lt_auto_input.py 설명)을 만든다.

## 6. 원고
- 발행 시간 순서대로. 묶음 첫 글 전에 공식 자료를 실제로 열어 사실 확인(원고지침 6번 검색 상한).
- 글마다 `작업폴더/원고/NN_YYYYMMDD-HHMM_키워드.md` 하나: 코드 블록 A(본문) + 코드 블록 B(메타데이터)를 원고지침 18번 형식 그대로.
- 다 쓰면 점검: 분량, 피할 표현 0개, {{LINK:}} 순서, 카테고리 이름 6개 중 하나, 본문 링크 확인, 표지 글자 수.
- 2편 쓸 때마다 짧게 진행 상황을 알린다. 사용자에게 질문하지 않는다(⚠로 남김).

## 7. 앱 입력
1. 미리보기: `python tools/lt_auto_input.py --week YYYY-MM-DD` (아무것도 안 씀, 바뀔 목록만 보여 줌)
2. 사용자에게 미리보기 요약을 보여 주고 "넣어"를 받으면:
   `python tools/lt_auto_input.py --week YYYY-MM-DD --apply`
   - 키워드 승인·직접 추가 → 원고 붙여넣기 → 메타데이터 저장 → 이미지 일괄 생성 → 최종본 만들기 → 예약일시 저장(발행 칸 미리 채움)
   - 이미지 생성은 비용이 든다(OpenAI). 미리보기 맨 아래에 총 장수·예상 비용(어림)이 나오니 `--apply` 전에 사용자에게 알려 준다. 특정 글만: `--only 1,3`, 이미지 건너뛰기: `--skip-images`.
3. 끝나면 사용자에게: 넣은 글 수, 실패한 글, 발행 순서표(날짜·시각·제목·최종본 주소)를 준다.

## 8. 사용자 몫 (Claude가 하지 않음)

- 색인 요청.
