# 주간 수집 순서서

사용자는 비개발자입니다. 보고는 쉬운 말, 표와 번호로 합니다.
근거 자료: `preview/ego_test_20261108/round3_report.md` (화면·버튼 방법을 확인한 시험 결과)

## 지켜야 할 것
1. 앱 코드(.py·templates·config)와 실제 데이터(articles*.json, content_queue*.json, perf_*.json)는 **읽기만** 합니다. 이번 작업으로 새로 생기는 것은 `perf_inbox/` 아래 파일뿐입니다.
2. ego lite 에서는 **보기 조작(주간·탭·페이지·이전 기간·달력)과 다운로드만** 합니다. 글쓰기·수정·삭제·발행·설정 저장·링크 발급·링크 복사 버튼은 누르지 않습니다.
3. **정산·계좌 정보는 기록하지 않습니다.** (정산 관리 화면은 열지 않아도 됩니다.)
4. 로그인이 풀려 있으면(스크립트가 `LOGIN NEEDED` 를 출력하거나 로그인 화면이 보이면) **멈추고 사용자에게 알립니다.** 비밀번호를 입력하지 않습니다.
5. 기존 파일을 바꿔야 할 일이 생기면 그 파일마다 `파일명.backup_before_작업명_날짜.확장자` 백업을 먼저 만듭니다(원칙적으로 새 파일만 만듭니다).
6. 작업 전·후에 `articles*.json`, `content_queue*.json`, `perf_*.json` 의 SHA-256 을 비교해 같은지 보고합니다.
7. 코드를 고친 경우에는 끝나고 `reviewer` 서브에이전트로 검수받고 결과까지 보고합니다.

## 기준 기간
- **지난 완료 주(월~일)**. 오늘이 일요일이어도 그 주는 아직 끝나지 않은 주입니다(네이버 주간 선택에도 나오지 않음).
- 처음 한 번에 여러 주를 받을 때는 시작 주 월요일부터 지난 완료 주까지 모두 받습니다.
- 주 폴더 이름 = 그 주 월요일 `YYYY-MM-DD`. 예) 2026-10-26 폴더 = 10.26(월)~11.01(일).

## 받을 것과 저장 위치
받은 파일은 다운로드 폴더를 거치지 않고 스크립트가 바로 저장합니다(`download.saveAs`). 다운로드 폴더 원본은 건드리지 않습니다.

| 번호 | 받을 것 | 저장 파일 |
|---|---|---|
| a | 지표 다운로드 → 조회수 순위(주간) | `perf_inbox/<주>/raw/rank_weekly_<주>.xlsx` |
| b | 지표 다운로드 → 유입분석(주간) | `perf_inbox/<주>/raw/referer_weekly_<주>.xlsx` |
| c | 쇼핑커넥트 판매 실적 엑셀(최근 30일) + 그래프 날짜별 클릭 | `<마지막 주>/raw/sales_30d_<끝날짜>.xlsx`, `clicks_daily_chart.csv` |
| d | 발급 링크 관리 목록 | `<마지막 주>/raw/links_list.csv` |

c, d 는 주마다 따로 받지 않고 **마지막 주 폴더 raw/ 에 한 번** 둡니다. 연결 스크립트는 `sales_30d_*.xlsx` 가 있는 가장 최근 raw 폴더를 자동으로 씁니다(주문 날짜로 주를 나눔). 30일을 넘는 옛 주문은 매주 받아야 이어집니다.

## 순서
스크립트는 이 폴더에 있습니다. **매번 새 파일(round-01.mjs …)로 복사해서 위쪽 상수만 바꿔** 실행합니다(예전 파일을 고쳐 다시 돌리면 지난 단계가 반복됨).
작업 폴더: `C:/Users/js625/ego/weekly-collect-<날짜시각>/` 처럼 새로 만든 곳. 실행 방법(PowerShell):

```powershell
ego-browser nodejs -e "await import('file:///C:/Users/js625/ego/weekly-collect-<날짜시각>/round-01.mjs')"
```

1. 작업 공간 이름은 `weekly collect` 로 하나만 씁니다(`taskSpace("weekly collect")`).
2. **a, b** — `collect_blog_weeks.mjs`: `WEEKS`(월요일 목록)와 `DAYS`(`[달력에서 누를 수요일 숫자, 이전 달 클릭 횟수]`)를 바꿔 실행.
   - 방법: `admin.blog.naver.com/beafather/stat/download`(지표 다운로드) → 데이터 종류 선택 → "주간" → 달력보기에서 그 주의 날짜 클릭 → "지표 다운로드".
   - 스크립트가 달력 클릭 뒤 기간 표시(`2026.10.26. 주간`)가 원하는 주와 같은지 확인하고, 다르면 `MISMATCH` 를 찍고 그 주는 받지 않습니다. 출력에 `OK` 가 6개(주×2)인지 확인합니다.
   - 한 주에 약 30초.
3. **c** — `collect_brandconnect_sales.mjs`: `OUT` 을 마지막 주 raw 로 바꿔 실행.
   - 방법: `brandconnect.naver.com/997658497773120/affiliate/sales-dashboard` (기본 "최근 30일") → "상품별 판매 실적" 오른쪽 **다운로드 아이콘 버튼**(글자 "엑셀 다운로드"를 눌러도 반응 없음).
   - 그래프(주황 선=클릭 수)의 선 좌표를 왼쪽 눈금으로 환산해 날짜별 클릭을 만들고, **합계가 화면 "실적 요약 → 클릭 수"와 같은지 확인**합니다. 출력의 `MATCH`/`MISMATCH` 를 보고서에 적고, 다르면 그 표시를 `clicks_daily_chart.csv` 맨 아래 줄과 보고서에 남깁니다.
4. **d** — `collect_brandconnect_links.mjs`: `OUT` 을 같은 폴더로 바꿔 실행.
   - 방법: 판매 실적 화면 위쪽 "발급 링크 관리"(`/affiliate/products-link`) → 10개씩 쪽 번호를 눌러 전부 읽음. 저장 열: 상품ID(상품 주소 끝 번호)·상품명·스토어·수수료·예상 수익·진행 상태·링크 발급일. 링크 URL 은 화면에 "복사" 버튼뿐이라 읽을 수 없어 넣지 않습니다(복사 버튼은 누르지 않음).
5. **연결·요약** (읽기 전용, 파이썬 새 파일 `tools/weekly_collect_join.py`):

```powershell
python -I tools\weekly_collect_join.py --all
```

   - 모든 주 폴더에 `posts.csv`, `search_terms.csv`, `orders.csv`, `clicks_daily.csv`, `summary.md` 를 만들고 `perf_inbox/summary_4weeks.md`(합본)를 만듭니다. 한 주만: `--week 2026-10-26`.
   - 끝에 주마다 "조회수 합계 / 파일 합계 / 일치" 가 한 줄씩 나옵니다. **불일치가 있으면 보고서에 크게 적습니다.**
6. **검증**
   - 각 주 `posts.csv` 조회수 합계 = 네이버 화면 합계(조회수 순위 화면의 주간 합계 또는 xlsx 합계). 일치해야 합니다.
   - 쇼핑커넥트 클릭: 환산 합계 = 화면 합계.
   - `articles*.json`, `content_queue*.json`, `perf_*.json` 해시가 작업 전과 같음.
7. 끝나면 ego 작업 공간을 `await task.finish({ keep: [] })` 로 닫습니다(성공했을 때만. 로그인 문제로 멈추면 닫지 않고 알림).

## 연결 규칙 (weekly_collect_join.py)
- 글: 네이버 글 제목을 `articles_naver_tips.json`(네이버 살림)·`articles_shop_naver.json`(옛 숍 네이버)의 네이버 제목과 맞춥니다(공백·기호 무시). 정확히 같으면 "제목일치", 비슷(0.85 이상)하면 "비슷한 제목", 아니면 "미연결". 장부 칸: 글 유형=메모 "글 유형:", 카테고리=메모 "카테고리 제안:", 발행일=`platform_published_at`.
- 발행 뒤 몇 주째: 네이버 작성일(없으면 앱 발행일)이 속한 주 = 1주째.
- 장부에는 있는데 그 주 순위에 없는 글은 "장부 전용(조회 0)" 줄로 넣어 평균이 부풀지 않게 합니다. 합계에는 영향 없음.
- 주문: 주문 엑셀 상품명 → 발급 링크 목록(상품명 일치) → 그 상품이 들어간 앱 글. 글 안에 상품ID 가 있으면 "링크일치", 지금은 장부 글 안에 `[구매링크]` 자리표시만 있어 대부분 **상품명 낱말로 맞춘 "상품명 추정"** 입니다. 주문일보다 늦게 발행된 글은 후보에서 뺍니다. 못 찾으면 "미연결".
- 검색어 횟수: 화면은 %만 보여 주므로 `비율 ÷ 그 주 최소 비율`(0.29%≈1회)로 추정합니다.
- 요약에서 표본이 5편 미만인 칸은 "판단 보류".
- 연결하지 못한 것은 `summary.md` 6번에 모두 나옵니다.

## 알려진 한계
- 오늘 주(미완료 주)는 네이버에 없습니다. 월요일에 "주간 수집"을 하면 방금 끝난 주가 받아집니다.
- 쇼핑커넥트 엑셀·그래프는 최근 30일만 보입니다. 31일 이상 지난 주문은 이미 저장해 둔 raw 로만 남습니다.
- 그래프 환산은 화면 그림 기반이라, 화면 구조가 바뀌면 `MISMATCH` 로 알 수 있습니다.
- 발급 링크 목록에 링크 URL 이 없어 URL 로 글을 찾는 연결은 아직 못 합니다.
